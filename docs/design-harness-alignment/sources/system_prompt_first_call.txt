### /knowledge_docs/knowledge/lumen-dsl/grammar.md

# Lumen DSL — Grammar Reference

The compact, precise reference for the Lumen DSL surface. DSL text compiles into
canonical `Scene` operations. It is line-oriented and indentation-sensitive.

## Line shapes

```
line       = indent , ( checkpoint | comment | page | element | directive | modify )
indent     = { "  " }                 # exactly two spaces per level
checkpoint = "//" text                # labeled history anchor
comment    = "#"  text                # ignored (note: a leading "#ref" is a modify line, not a comment)
page       = "page" id [ page_property* ]
element    = id kind property*  |  kind id property*    # either order
directive  = verb "(" args ")"        # delete / parent / clone / replace / ungroup / …
modify     = "#" ref property*        # targeted edit of an existing object
```

Rules: two spaces per indent level (`LUMD0301`); never indent more than one level
deeper than the parent (`LUMD0302`); only containers may hold children
(`LUMD0304`); `page` lines must be top-level (`LUMD0305`).

## Page header

```text
page page_a4 preset(a4,portrait)          # preset(name, orientation?)
page story size(1080,1920,px)             # size(width, height, unit)
```

- Presets: `a4`, `us_letter`, `linkedin_ad`, `envelope_dl`, `custom`
  (unknown → `LUMD0223`). Orientation: `portrait` | `landscape` (unknown →
  `LUMD0224`); A4/Letter default portrait, ad/envelope default landscape.
- Units: `px`, `mm`, `in`/`inch`, `pt` (unknown → `LUMD0252`). Dimensions must
  be positive (`LUMD0251`). `size(...)` needs all three args (`LUMD0250`).
  New page commands normalize to canonical `pt` artboard bounds while preserving
  the requested source/export size.
- Presets are shortcuts only. **Never fake a square ad as a square frame inside an
  A4 page** — set the page size.
- Child `p()`/`s()` values are authored in canonical layout points and are
  artboard- or parent-local. Do not use physical `mm` or renderer pixels for
  child coordinates.

## Node kinds

Containers (may have children): `frame`/`fr`, `group`/`gr`, `autolayout`/`al`.
Leaves (no children, `LUMD0304` if nested): `rect`/`r`, `ellipse`/`e`/`c`,
`line`/`l`, `text`/`t`, `image`/`img`, `vector`/`v`, `svg`, `instance`/`inst`.

```text
hero fr p(0,0) s(595,160) fill(#ffffff) rd(16)
  title text "Welcome" p(24,24) s(440,hug) font("Inter",28,700,left)
```

Unknown kind → `LUMD0206`. Duplicate node id → `LUMD0401`. Node outside a
page/container → `LUMD0402`. `image` needs `asset(id)` (`LUMD0403`); `vector`
needs `path("…")` (`LUMD0404`); `instance` needs `source(id)` (`LUMD0405`).

**`image_policy(…)` — slot-modify lines only** (`#slot:key` / `#slot_id:id`).
Sets the *image policy* on an image-like slot. Forms:

```text
#slot:account.logo image_policy(contain)                  # bare fit mode
#slot:account.logo image_policy(fit=cover, focal_x=0.5, focal_y=0.35)
#slot:hero.shot    image_policy(fit=cover, min_dpi=300, aspect=1.5,
                                preserve_transparency=false)
#slot:account.logo image_policy(none)                     # clear the policy
```

Fields: `fit` (`cover`|`contain`|`crop`), `focal_x`/`focal_y` (0..1, given
together), `min_dpi`, `aspect`, `preserve_transparency`. Anything you leave out
takes the default (`fit:cover`, transparency preserved, nothing else asserted),
so a short form is a complete policy — you never end up half-configured.

You will rarely need this: **a slot created by `image … slot(key)` is already
born with the default policy.** It exists for slots that predate that behavior
and arrive without one — the fix for a `LUMV0820` on a document you did not
author. If you see `LUMV0820`, this one line clears it; do not delete the slot.

Assets / vectors: `asset(id)`, `path("…")`, `source(node)`, `to(x,y)` (line end).

Any other property name → `LUMD0212 unknown property`. A property used on the
wrong node kind warns (e.g. `font(...)` on a non-text node → `LUMD0601`).

## Two ways to change an existing scene

1. **Continuation** — append new nested element lines under an existing container

2. **Modify line** — `#<ref> prop(...)` edits an existing object in place. Refs:

### /knowledge_docs/knowledge/lumen-dsl/directives.md

# Lumen DSL — Directives & Targeted Edits

These are how you change an **existing** scene surgically, without re-declaring
the page or re-authoring nodes. This is the heart of reliable repair: a diagnostic
that names a node should be fixed with one of these, not a full rewrite.

All of the directives below are lowered to checked operations and covered by
tests. The one exception is `ds(...)` (design-system switch), which is parsed but
not yet lowered (`LUMD0700`); `undo()`/`redo()` require a history adapter.

## Modify line — `#<ref> prop(...)`

Edit one existing object in place. The ref selects what you target:

| Ref form | Targets | Example |
|----------|---------|---------|
| `#node_id` | a node | `#headline s(440,hug) font_size(22)` |
| `#page:id` | a page | `#page:page_a4 size(1080,1920,px)` |
| `#slot:key` | a slot | `#slot:contact.name required(true) sample("Jane Q. Patient")` |
| `#slot:key` (image) | an image-like slot's policy | `#slot:account.logo image_policy(cover)` — the `LUMV0820` fix |
| `#asset:id` | an asset | `#asset:logo_main name("Primary logo")` |
| `#export:name` | an export profile | `#export:web format(png)` |
| `#document` | document metadata | `#document medium(print)` |

A leading `#ref` line is a **modify**, not a comment. Properties that don't apply
to the target type warn (e.g. `font(...)` on a page → `LUMD0903`). Missing target
→ `LUMD0901`.

**The #1 ref mistake** (observed to burn whole runs):

```text
#page_a4 size(1080,1350,px)        ✗  bare #page_a4 is NODE grammar → LUMD0901
#page:page_a4 size(1080,1350,px)   ✓  pages need the #page: form
```

```text
# Fix an overflowing instruction box — change only that node:
#instruction s(352,140) max_lines(6) lh(1.4)
# Or make its card taller instead:
#card s(400,560)
```

## Structural directives

All structural directives take **NODE ids only**, never page ids —
`replace(page_a4)` halts `LUMD0901`. To rebuild a page's content, keep the page
and `replace(<its existing root node>)` with your new single-root subtree.

| Directive | Form | Use |
|-----------|------|-----|
| `delete` | `delete(id [,if_exists] [,hard])` — also `delete(page:id)`, `delete(slot:key)`, `delete(asset:id[,hard])`, `delete(export:name)` | remove a node/page/slot/asset/export profile; `if_exists` downgrades a missing target to info |
| `parent` | `parent(id, pid [,index:N \| before:anchor \| after:anchor])` | re-home a node |
| `before` / `after` | `before(id, anchor)` · `after(id, anchor)` | reorder siblings |
| `clone` | `clone(src, new_id, after:anchor [,slots:copy\|detach\|suffix:_x] [,computed:clear\|preserve])` | duplicate a subtree (e.g. another card) without re-authoring it |
| `replace` | `replace(id [,slots:preserve])` then an indented single-root subtree | swap a node's subtree atomically |
| `ungroup` | `ungroup(id [,allow_layout])` | dissolve a group, keeping child order |
| `override` | `override(clone_root)` then indented `#child …` modify lines | vary one cloned instance |
| `remove_effect` | `#node remove_effect(effect_id)` | drop one shadow/effect by id (modify-line only; else `LUMD0616`) |

```text
# Duplicate a card and tweak just the copy:
clone(card_a, card_b, after:card_a, slots:suffix:_b)
override(card_b)
  #card_b p(520,221)
  #title_b text "Second Option"
```

Bad syntax in any of these → `LUMD0207`. Block `replace` requires exactly one
staged root (`LUMD0914`). Its replacement subtree needs fresh ids throughout,
including its root: it stages alongside the old subtree before the swap. Use
`reconcile` when retaining existing ids.

`parent` takes a bare node id as its second argument: `parent(logo_mark,logo_chip)`.
For a page parent, use `parent(logo_mark,page:page_a4,0)`. The `parent:` prefix is
a **clone placement** form; it is not valid in the `parent(...)` directive.

## Reconcile a container — `reconcile(<container_id>)` + subtree

`reconcile(target)` is THE way to **add, remove, or restructure** the children of
an existing container. Indent the container's **full intended child subtree**:
re-emit every child you want to keep (same id, same fields) alongside the ones you
add or change. The engine diffs the block against the live subtree and emits the
MINIMAL operations — an unchanged re-emitted child costs zero ops.

```text
reconcile(hero)
  eyebrow text "INTRODUCING" style($type.eyebrow)     # unchanged → no-op
  headline text "New Headline" style($type.h1)        # kept id, new copy → update
  cta_shot image asset(asset_ing_9394e96d) p(0,0) s(400,300)   # new id → insert
```

Re-emitting existing ids inside the block is the POINT, not a duplicate-id error:
the block stages DETACHED, duplicate-id checks (`LUMD0401`) are suspended inside
it, and it never applies directly — only the computed diff ops do.

**Diff semantics** (by child id):

- present in both block and live subtree → `UpdateNode` with only the changed
  fields (`MoveNode` if its parent/index changed); identical → zero ops.
- in the block only → `InsertNode` at its block position.
- in the live subtree only → depends on **provenance** (the protection rule).

**The protection rule** (the human contract):

- An **agent-authored** live child omitted from the block is REMOVED — the
  declarative contract for the agent's own material.
- A **protected** child (seed-born / human) omitted from the block is **KEPT**,
  with a loud `LUMD0262` warning — omission never deletes human content. To remove
  protected content, write `delete(<id>)` explicitly (allowed inside the block).
- A protected child re-emitted with changed fields IS updated (an explicit
  re-author, same legitimacy as a `#node` modify line).

`reconcile(target)` requires a NODE container — frame/group/autolayout — never a
page id (`LUMD0264`, which names the valid containers in the live scene). To fill
an *empty* page use the `#page:<page_id>` continuation form instead. Each close
emits one `LUMD0263` info summary: `reconciled <container>: N updated, N inserted,
N removed, N moved, N kept-protected`.

```text
# Add a testimonial under `main` and drop the old placeholder, keeping the rest:
reconcile(main)
  headline text "Trusted by teams" style($type.h2)   # kept verbatim
  quote text "\"Best tool we've adopted.\"" style($type.body)   # new → insert
  attribution text "— A. Patient" style($type.caption)          # new → insert
```

## Repair discipline (do this, not that)

- **Do** target the failing node with a `#id` modify, a `delete`/`parent`, or a
  scoped `apply_structured_edit`.
- **Do NOT** re-emit `page …` or re-declare existing node ids — that is a repair
  *failure* (`LUMA0200` / duplicate id), and the partial deletes it often pairs
  with can wipe the good scene.
- For a precise, *checked* edit on a named node, prefer the tool
  `apply_structured_edit` with a `scope` over hand-writing DSL — it fails closed if
  the edit would touch anything outside the named target. See `skills/repair-design`
  and `skills/tools`.

# Artboard Frame Authoring

Use this reference for every generated exportable artifact.

## Canonical Geometry

Lumen authoring uses canonical layout points (`pt`) for scene geometry:

- A4 portrait preset: about `595 x 842 pt` layout bounds, with print metadata
  of `210mm x 297mm`.
- US Letter: `612 x 792 pt`, with print metadata of `8.5in x 11in`.
- LinkedIn square: `1080 x 1080 pt`, with raster export defaulting to
  `1080 x 1080 px`.
- LinkedIn wide: `1200 x 628 pt`, with raster export defaulting to
  `1200 x 628 px`.
- Custom `6in x 4in`: `432 x 288 pt`, with print metadata of `6in x 4in`.

The agent should author only against layout bounds. Do not use `mm` for child
`p()` or `s()` values. Do not treat renderer pixels as scene coordinates.

## Root Structure

Preferred generated structure:

```text
page page_a4 preset(a4,portrait)
  artboard al(v,g(18),pad(36)) p(0,0) s(fill,fill) fill($surface.page) clip(true)
    card al(v,g(12),pad(18)) p(0,0) s(fill,hug) fill($surface.card) rd(12)
      ...
```

Do not put `background(...)` on a `page ...` creation line. Use the root
artboard/frame `fill(...)` for first-pass backgrounds. Page background changes
belong to explicit `#page:page_id background(...)` modify repairs when the
repair request grants that surface.

Do not create a separate top-level `bg` rectangle for the artboard background.
Only use a separate background-like node when it is a real layered visual object
inside the composition.

## Artboard-Local Coordinates

Children of an artboard are local to that artboard. A node at `p(24,24)` on an
A4 page is `24pt` from the artboard top-left, not `24mm` and not `24px` in the
renderer. Children of a card or stack are local to that parent.

Use parent-relative layout before absolute placement:

- `fill` for width/height that should use available parent space.
- `hug` for text or sections whose content can vary.
- `al(...)`, `pad(...)`, `g(...)`, and `wrap(true)` to keep child groups inside
  parent bounds.
- fixed point values only where the visual size is intentional.

## Anti-Patterns

Avoid these patterns in generated or repaired export-safe designs:

- A4 page plus child values authored as if the page were `210 x 297`.
- Hardcoded page-sized root/background dimensions such as `s(595,842)` or stale
  raster dimensions after a resize. Use a clipped root frame `s(fill,fill)` and
  `fill(...)` for export-safe artboard backgrounds.
- `card s(170,210)` with descendants still `s(400,...)`.
- loose top-level `bg`, `card`, or `header` nodes that exceed the artboard.
- switching from `px` to `mm` to make a preview look smaller.

If one parent is resized, inspect and update the affected descendants in the
same layout cluster.

# Shared scene composition and native components

Compose from the message and inspected advertiser-relevant references. Identify
the visual invariants first: focal scale, type/image relationships, reading order,
material behavior, characteristic spacing and authentic identity treatment.
Translate those relationships to this content; no full-page skeleton is binding.
Establish one dominant
element, a clear second read and intentional space. Components are reusable
mechanics, not fixed proportions, mandatory cards or required layout patterns.
Recompose for the actual words, imagery and aspect ratio. Type-only is a valid
finished direction when imagery is optional; requested new artwork still needs
generation. CTA, eyebrow, benefit row and proof card are optional.

Use native editable text for copy, native geometry for frames, simple paths,
connectors and meaningful UI-independent diagrams. Use real independently
placeable images for logos and authentic product screenshots/photos. Never
redraw, recolor or typeset a substitute logo. A recognizable authentic target
favicon may be a deliberate account identity anchor; it cannot replace an
explicitly required readable wordmark. Choose a supplied variant that fits its background. Missing
variants are gaps; a white plate is not the absent reversed logo. Preserve the
source logo's aspect and real clearspace guidance. Inspect visible ink against
the local background, including transparent padding and texture; containing the
file does not prove the visible mark is readable. Choose a contrasting authentic
variant or repair the surrounding composition. A group of separate unchanged
real logos and a native separator is valid; do not fabricate a merged or redrawn
company mark.

Related headline, support and action should read as one message group. Establish
that relationship through proximity, alignment and reading order suited to the
reference; unrelated regions need their own separation. A group can be asymmetric
and need no visible card or vertical stack. A headline and its explanation should
not become separate islands merely because each fits its own frame.

Work through the actual copy and its dependent layout together:

Size supporting copy with the approved headline, actual font and inspected brand
reference before allocating the image region. A kit's body role may describe
website text, not a scaled ad. Establish both the first read and a comfortable
second read: tiny support fails legibility, but enlarging it until it competes
with the headline fails hierarchy. Consider visible letter size, weight,
contrast, copy length and grouping together; nominal font size alone cannot
choose the right relationship across different faces or brands.

When a user supplies a corrected composition, inspect its current resolved
typography and keep that relationship for this design's repairs and requested
variants. The saved scene is evidence of that local choice, not a global brand
preference or proof that another run has learned it. For a fresh design, inspect
the references and preference context actually available to that run. Do not
transfer one brand's chosen size or type ratio to unrelated brands or formats.

The diagnostic `resolved_font_size * viewing_width / page_width` explains how
type scales; it is not a universal size target. If a caller explicitly selected
a numeric review profile, satisfy it alongside visual hierarchy; report a
conflict with an approved treatment rather than silently overriding that
treatment. With no selected profile, do not invent a numeric acceptance floor.
Preserve an approved headline and change support only as far as needed for the
second read. Give it enough width and height to wrap comfortably; a natural
single line is also valid. Use a supplied size token or checked explicit edit,
then inspect the resolved size because a role may override an authored fallback.
Reflow related spacing after type changes and compare the whole composition at
the same viewing scale; stop when the explanation is readable and subordinate.

1. Use brand tokens and the kit's available families/weights. Choose headline
   width from meaningful phrase breaks and the intended focal scale. Choose
   support width from its own words and available space; it need not match the
   headline width. If support wraps awkwardly, inspect whether a wider measure
   improves it before reducing type size. Prefer content-hugging text height;
   reserve fixed-height slots only when the composition needs them. Kit role
   sizes are source values, not universal ad sizes. No fixed width, line count,
   type ratio or margin fraction follows from this procedure.
2. After preflight, use `inspect(view="geometry", target=<node_id>)` for the
   related text and container nodes. `computed.layout_bounds` describes the
   allocated box; `computed.render_bounds` is not a glyph-ink silhouette.
   `computed.text_lines`, when present, gives each measured painted line box,
   including horizontal/vertical alignment, in page-space unrotated coordinates.
   For ordinary untransformed text, compare the last headline line with the
   first support line and the support's last line with the action. Check the
   visible ink in the current render too: line boxes are not pixel-tight optical
   bounds. Missing/stale geometry, font fallback, heuristic measurement or
   transformed ancestors limit what those numbers establish.
3. Repair the cause of a disconnected group: excess fixed-height slack, a stale
   vertical offset, an unnecessarily narrow support box, or unrelated padding.
   Preserve an approved headline when the support's measure and position are the
   problem. Adjust dependent positions after reflow; don't leave the CTA at its
   old coordinate after the paragraph above it changes height. Use an existing
   auto-layout group's `g(...)`/`pad(...)` where it expresses the relationship,
   or repair the affected parent-relative positions together. Inspect the tree
   before reparenting; structural grouping is not proof of visual grouping.
   When inspection reports a pinned node, honor its authoritative `absolute_box`;
   changing ordinary position fields alone may not move it.
4. If the direction includes a CTA, keep its native label and any button geometry
   in one coherent component, with content-driven padding and brand-supported
   corners. Measure the actual label, then check the whole component's relation
   to the message it acts on. Avoid an independently floating label or detached
   action island. A text CTA needs no invented button frame; a creative without
   a CTA needs no reserved action row.

For emphasis within a sentence, prefer a supported span in one native text node
so the phrase reflows together. The DSL's `[[phrase]]` plus `span(...)` supports
solid/token fill, weight, italic and decorations; it cannot change a span's family,
size or leading. Use only supplied faces. Weight/italic can change line breaks,
so remeasure after emphasis changes. `span(...)` is creation syntax; later edits
use checked structured span operations. A content edit clears old spans: restore
the intended emphasis against the new words. See `knowledge/lumen-dsl/text.md`
for exact syntax and limits. Separate native nodes are appropriate for distinct
independent text roles; coloring one phrase alone is not a reason to split a
headline into manually positioned pieces. Review product names and phrase breaks
after every width change, and revise validated copy explicitly if words change.

Quotes and metrics use independent native text with source-backed qualification
and attribution where needed. Their treatment follows the inspected examples,
not a compulsory card. Use native connectors only when the relationship is real.

Page before spend: on a pageless document compile explicit page dimensions before
logo or image operations. Required authentic target-logo acquisition permits
page-only source preparation before the first complete direction: fetch and view
the real logo, then validate the direction with its returned asset ID. Creative
nodes and artwork construction, including new imagery spend, follow validated
direction. Reserve artwork as an empty leaf `fr`.
For a real raster/logo asset, `asset(action="place", ...)`
accepts that frame or an existing image: it changes the leaf to an image in
place, preserving its ID, parent/order and geometry. It cannot consume a frame
with children or create a missing target. Missing asset IDs remain errors.
Path-backed vector assets remain native vectors.

Small mechanical example, using the public tool calls (dimensions illustrate
the reservation only; they are not a composition template):

```python
import json

compile_dsl_block(source='''page sample size(640,240,px)
  artwork fr p(11,23) s(480,128) rd(12) clip(true)
  caption text "Independent native copy" p(11,170) s(480,hug) font_size(20)
''')
# When new artwork is needed; [] deliberately uses no references in this example.
generated = json.loads(asset(action="generate_image", target_node_id="artwork",
    prompt="An isolated folded paper form, no text or logos", reference_asset_ids=[]))
art_id = generated["image"]["asset_id"]
view(target=f"asset:{art_id}")
# After inspecting a successful real output:
asset(action="place", asset_id=art_id, node_id="artwork", fit="contain")
```

For a known existing asset, skip generation and place its real ID into the same
reservation; kit assets use `asset(action="use_brand_asset", asset_id=..., node_id="artwork")`.
Direct DSL `image asset(<real_asset_id>)` is also valid. If a frame must remain a
viewport/container, retain it and add an image child only once its real asset ID
is available, using the checked DSL directives. An `image`/`img` declaration
always needs `asset(...)`; no dummy ID or blank image is needed before placement.
Don't generate a flattened complete ad. Text, CTA, logo and product pixels remain
independent layers.

Logos use contain with clear space; product crops preserve the relevant UI or
object. Don't destructively crop an asset just to rescue a preselected skeleton.
Read `knowledge/scene/references.md` when generating a component.

Image fit changes pixels inside the node, not the node's layout bounds. Keep a
product image node inside its intended viewport, with parent-relative geometry.
Use `place` with cover/focal for a verified crop or contain for the intact source.
Do not progressively enlarge and offset a child beyond its parent to guess a
crop; this causes bounds failures even with contain. A clipping parent does not
make overflow valid, and `bleed(true)` is not a repair for missing product content.
If the desired crop cannot preserve the meaningful UI, adapt the frame to the
whole source or choose a different source. Keep tabs, labels and proof named in
the copy readable; inspect geometry once and repair the complete image/frame
pair together instead of spending several compiles on coordinate nudges.

For exact source-pixel extraction, inspect the original image and its dimensions,
then use `asset(action="crop_image", asset_id=..., crop_rect=[left, top, right, bottom])`.
Use integer bounds in original pixels, not preview pixels:
`0 <= left < right <= source_width`, `0 <= top < bottom <= source_height`;
right and bottom are excluded. The source stays intact and the result is a new
image asset. Inspect it before explicitly placing it in an independent image node
with `asset(action="place", ..., fit="contain")`. Cropping cannot remove a background
baked inside the selected rectangle or recover missing/occluded product content.

An inspected reference's soft material, blur, tonal variation or texture is part
of its treatment. A flat brand-color rectangle does not preserve those properties.
Reuse appropriate source artwork or generate the separately placeable treatment;
use a flat field only when that is the intended and justified visual direction.

Author through `compile_dsl_block` or supported checked operations only. The
DSL grammar/directives and artboard-frame reference are authoritative mechanics.
Reparenting changes parent-relative placement and paint order. Inspect the new
tree and geometry; an unindexed `parent(...)` can move content before its former
background. For deliberate ordering, use `before`, `after` or indexed `parent`
from `knowledge/lumen-dsl/directives.md`, then check the result. Managed siblings
paint in stored order; pinned absolute nodes use a separate page pass above
managed content and escape ancestor clipping (the page still clips them).
Use measured geometry for repairs and keep unrelated existing content intact.
After changes: preflight, render, view the actual composite and repair the
specific failure. Components that compile still need visual judgment.
