# Product or capability guide task

Research exactly the supplied offering ID, name, official page and aliases. Use sibling offerings to disambiguate, not to fill missing features. Follow the complete official product FAQ and relevant setup/API/release documentation. Distinguish current product, capability, package, beta and historical names. Explain an uncertain capability as such instead of promoting it into a standalone product.

Required core sections: Overview; Who it is for; Capabilities and limits; Workflows and use cases; Integrations and setup; Pricing and packaging; Differentiation; Customer evidence; Sales discovery. For a developer or uncertain capability guide, use the host-supplied narrower headings while covering supported users, interfaces, dependencies, availability and questions.

Write a complete guide a salesperson and technical evaluator can use. Separate purchaser, champion, administrator and daily user. For each major use case, describe the starting situation, inputs, product action, handoff, resulting workflow and relevant limits. A desired improvement is not a guaranteed numeric outcome. Use a compact capability → workflow → dependency → limitation/evidence table where helpful.

Explain integration routes: native/direct, relayed through another system, API/custom build or merely listed. Separate data read from write/action support; endpoint existence does not prove autonomous execution permission. Do not infer security controls or implementation effort.

Link to the authoritative pricing research for package context; do not invent standalone pricing from a suite. Retain the billing unit and source scope if quoting a number. Differentiate using product-specific facts; attribute vendor comparisons. Use customer proof only when the source names this product or clearly describes its workflow; otherwise keep it at company level.

End with pointed discovery questions whose answers select or rule out this offering. Unknown information is a question, not an invented feature or disqualifier. Do not equate missing documentation with absence of capability. Target about 700–1,200 useful words for a substantial product, adjusting to evidence rather than padding.
