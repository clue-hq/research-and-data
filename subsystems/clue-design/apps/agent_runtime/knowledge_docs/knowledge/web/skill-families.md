# Website skill families

Seven families group the responsibilities below through existing callable tools. A
family is a group of skills, not a separately running agent. Entry files are
short; read their detailed references for the operation at hand. This works
from a workspace's captured brand sources, not a hardcoded customer pack.

The runtime includes `create-website/references/source-format-contract.md` in
every website role's prompt, including new projects with no saved instructions.
It supplies the shared retrieval, preservation, identity and final-review rules;
the families below supply task-specific depth. Model compliance still needs
observed trace and rendered proof; presence in context alone is not qualification.

| Family | Responsibilities | Skills |
|---|---|---|
| Source readiness | observed-page acquisition; coverage/freshness/version; provenance/dependencies; gap/refetch handoff | `web-source-readiness` |
| Source-faithful composition | observed brand grammar; pin/rebind/variant/repair choice; responsive/root/asset preservation; chrome/CTA consistency | `create-website`, `design-guidance`, `repair-cloned-sections`, `campaign-page-workflow` |
| Media composition | role/rendition/provenance; product crop/radius/alpha; authentic product on its branded stage; coherent type hierarchy; proof/logo identity | `web-media-composition`, `web-product-story` |
| Motion fidelity | inventory; supported reconstruction/fallback; state/playback verification | `web-motion-fidelity` |
| Personalization | page/audience intent; identity/evidence/use gates; useful decision exhibits; eligible contact relevance; grounded copy and purpose-led action | `web-account-personalization`, `web-decision-material`, `web-contact-personalization`, `campaign-landing-page`, `conversion-copywriting` |
| Scoped editing | artifact/target/current state; minimal mutation; keeper properties and targeted verification | `edit-website` |
| Fidelity review | source/final-state comparison; responsive/interaction/action/provenance; useful material and preserved strengths; honest verdict/gaps | `review-website` |

For new pages: source/evidence readiness → argument, decision exhibit and action →
composition/media/motion → rendered review. For a targeted edit: editing → only
the families affected → scoped review. `plan-design` owns the
existing plan. Neither overrides the measured source or user edits.

The workflow has real capability boundaries. Website agents use their current
workspace's registry and declared tools. `fetch_page` supplies facts and links,
not a rendered capture. Acquisition/refresh belongs to brand ingestion. Never
seed a customer-specific replacement catalog to make a run appear complete.
An unavailable source/read/refresh tool is a named gap, not a fictional call.
The director/solo performs render and behavioral review. The author reports
what it changed; a reviewer uses delivered observations and read tools.

A source faithful page may reuse captured HTML/CSS inside React WebDoc output;
that does not recover the original site's React source or WebGL program.
Generated media and authored custom TSX are derived work. Readiness, successful
compilation, approved assets and a clean static screenshot are separate from
visual and functional acceptance. Report each against observed evidence.
