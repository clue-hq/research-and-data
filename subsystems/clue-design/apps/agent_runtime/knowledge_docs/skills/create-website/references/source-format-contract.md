# Website source and format contract

Apply this in every project, including a fresh project with a short prompt and
no project instructions. The runtime supplies this shared skill reference to all
website roles. Role tool permissions still apply; an author hands rendering to
the director and a reviewer diagnoses without mutating.

## Retrieve before deciding

Use `web-source-readiness` to inspect the seller kit and candidate source bands.
Use `web-account-personalization` for scoped target research. Keep separate:
source visuals, seller capabilities, target evidence and the user's actual request.
A delegation brief or previous generated page is not a verbatim user instruction
or verified evidence. Fetch only missing relevant material; continue reported
pagination rather than repeating searches that return the same IDs. An unavailable
source remains a named gap, not permission to reconstruct it from memory.

## Preserve the selected component

Before assembly or composition, read `create-website`; before editing read
`edit-website`. A selected source component contributes its actual hierarchy,
layout, typography, spacing, image framing and responsive rules. Copy changes go
through existing slots, or `repair-cloned-sections`' exact-text/anchor lanes when
copy is unbound. Missing slots do not require new HTML/CSS. A request to personalize
or fix typography does not authorize a structural rewrite.

For a genuinely missing section, inspect an equivalent source role before raw
composition. Record actual heading/body/label faces, weights, sizes, line heights,
tracking, measure and breakpoint changes in the existing plan. Family aliases
alone are insufficient: a Regular display heading is not a Medium heading or a
sans body label. Do not shrink text to fit an oversized argument; edit the copy.

Render the selected source skeleton before composing missing text sections; reuse
its current render if one already exists.
Use `view("layout:1440")` to find its node IDs, then
`view("typography:node:<source-node-id>")` for one compact cross-viewport read.
Follow `next_target` for additional text paths; inspect `capture_coverage` and
per-width gaps. The view joins measured values, not guessed brand defaults or
inferred responsive CSS. Inspect source CSS for the actual breakpoint rules.
If source measurements are unavailable, report that gap rather than claiming fidelity.

For an existing selected text role, use `set_web_typography_reference` with the
same source and target before changing it. The compact view's `reference_path`
values are rendered paths at 1440/768/375; stored text-edit paths are different.

For a missing raw section, the new target ID does not exist before composition:

1. Choose an equivalent role in a source section that will remain on this page.
   Freeze it with its measured node/path as both reference and target.
2. Compose and pin the new section. Render the draft, then read its real target
   node/path through the layout index and compact typography view.
3. Map that new target to the exact source node/path frozen in step 1. The tool
   reuses the original frozen measurements, even after the document changes;
   it does not sample the later draft as a new reference.
4. Repair differences using the inspected source CSS, render, and check review.

Do not invent future node IDs or rendered paths. A self-bound source must remain
on the page because review also checks it; do not use a temporary section that
will be deleted. Never rebase a reference onto a drifted draft.
Unmapped or unmeasured roles stay unverified. This check covers typography only;
compare structure, content fit and behavior separately.

## Compose identity and product evidence deliberately

For account pages, put target identity in the opening content, above the main
heading, outside navigation. Keep seller identity in its appropriate source
treatment. A target logo is not a navigation item. An explicit user request for
another placement governs; an assistant's claimed approval without its user
source does not establish that exception.

Product imagery triggers `web-media-composition` and `web-product-story` before
placement: inspect real pixels, choose adequate resolution and distinguish a
finished composite from separate background/product layers. Preserve clipping,
corners and crop without adding a second frame. A captured control or
`controller_not_retained` triggers `web-motion-fidelity` even when the user did
not mention animation. Preserve its visual wrapper while implementing a supported
interaction; report any unsupported behavior rather than silently dropping it.

## Review the actual final version

Read `review-website` before judging. Compare current readable desktop/tablet/phone
strips, source roles and every required interaction state. One overview or last
tile is not a whole-page inspection; an old render cannot verify a newer document.
Check visible account reasoning and every CTA's label, destination and promise.
Successful pinning, a clean clone walk and a typography match do not establish
overall quality. Name unresolved structure, media, copy or behavior defects in
the existing finalization report. Repair the diagnosed scope; another generation
without new evidence is not a diagnosis.
