# Choose the action from the decision

Select the page's purpose before copying its source CTA. The original homepage's
button is a visual component and an available destination, not this campaign's
automatic offer. Neither a named account nor a researched person implies demo intent.

| Reader's immediate job | Appropriate action when supported |
| --- | --- |
| Understand relevance | Explore an actual workflow/use case on the page. This is navigation, not a booked meeting. |
| Compare fit or prepare an internal review | Open a real evaluation section, relevant technical resource or existing comparison. Do not invent a downloadable report. |
| Investigate an active opportunity | The supplied next step: existing meeting path, proposal, workshop or assessment, only at its actual supported scope. |
| Attend an event | Register through the real event destination with correct details. |
| Try or buy the product | Actual trial, demo or purchase flow, when that is the requested/supported campaign intent. |

Record four things in the existing plan: reader decision, promised receipt, exact
label and destination/behavior. If the purpose is unclear and would change the
argument, ask one consequential question before a costly build. For an exploratory
draft, make a useful reversible choice such as an in-page workflow link, explicitly
classify it as navigation and leave the unchosen sales action out. Do not pretend
this completes a requested lead-generation conversion flow.

One page can have a coherent primary action and relevant secondary resources.
Repeat an action where it helps the decision; a button in every band is not a
quality requirement. A no-sales-CTA brief remains valid.

Carry those decisions into the section plan's **Actions** field for every retained
source button, including unslotted labels: keep with its actual purpose, change
label and destination together, or remove it. Classify real secondary actions
explicitly. A valid inherited demo URL does not make an unwanted demo CTA relevant.
Use the exposed exact text/href repair when slots cannot carry the chosen words;
changing only the href leaves the source's visible promise in place. Inspect and
report unsupported removal/adaptation rather than silently accepting it.

For `assemble_abm_page`, supply chosen `cta_label` and `cta_href` explicitly when
using its header. The shell's compatibility fallback (`Book a walkthrough` →
`#contact`) is not an approved offer. A local anchor is valid only if its target
exists and does what the label promises. If the selected intent needs no header
button, choose appropriate supported composition instead of keeping that fallback.

Do not fix a mismatch merely by relabeling the same endpoint: a demo form cannot
be called “Get your evaluation” unless it actually provides one. Verify the real
destination and visible promise together before calling the page ready.
