# Distinct pages from the same brand and account evidence

Use when the user requests multiple concepts or substantially different page
directions. Ordinary account scaling and scoped edits keep their own contracts.
This is a short addition to the existing plan, not a new runtime schema or agent.

## Choose the directions before building

For each requested page, write one row in `workspace/plan.md`:

| Reader / decision | Selected evidence and limits | Central product mechanism | Opening message | Decision material visible on page | Section sequence | Visual emphasis / source ancestors | Actual next action |
|---|---|---|---|---|---|---|---|

For argument alternatives, give each page a useful reason to exist: an operator understanding a workflow,
an evaluator inspecting fit, or a sponsor considering the scope of an evaluation.
These are possible decisions, not assumed buying roles. Choose from the brief
and evidence; when authority is unknown, address the professional task without
claiming this person controls budget or has agreed to buy.

For layout-only alternatives, preserve the approved proposition and supplied copy.
Their purpose is to compare visual treatments of the same message, so qualify the
directions through composition, media emphasis, hierarchy and rhythm. Change copy
only where the user allows it; do not force a new argument into a visual comparison.

Evidence changes the argument. A published initiative can set the evaluation
context; it does not prove pain, purchase intent, adoption or a promised outcome.
Use only material insights. Keep conflicting, stale, restricted or unsupported
claims in the internal evidence notes, rather than making a longer dossier page.
For a researched account, initiative and contact set, each page must still explain
the product and provide enough relevant material to support its reader's decision.
Shortening one sibling or adding a salutation does not create a different useful
argument. Use the account decision map to identify what each reader can actually
learn from that page; share essential product context where it is needed.

## Make the visual difference serve the decision

Keep brand invariants fixed: seller typography, palette allocation, spacing scale,
image treatment, authentic marks and source behavior. Vary the way the argument
is presented where the request allows it:

- A product-led introduction can put a source product composition alongside the
  opening copy; the mechanism is visible before the visitor scrolls.
- An evaluation page can lead with a concise editorial proposition, then pair
  specific questions with product evidence instead of listing the whole catalog.
- A workflow page can give a source-derived sequence the main visual weight,
  with a close product detail explaining the relevant handoff.

Inspect the real library before choosing any of these. These are options, not
required layouts. If a healthy source band needs a different arrangement, derive
a campaign variant from its actual markup/CSS, preserving its responsive system
and lineage. Do not replace a source ancestor with an imagined lookalike.

For a requested set of different layouts, compare hero arrangement, section jobs,
visual weight, media treatment and surface rhythm. Three centered heroes followed
by the same product screenshot and gradient closer are still one composition,
even with different headlines or fewer sections. Section shuffling, recoloring
or new card icons alone do not establish a new direction. A source constraint may
limit variation; record it rather than claiming distinct layouts were delivered.

## Write and review as a set

Use the website copy brief for each page. When the request includes argument
alternatives, different headlines should express different useful arguments, not
three synonyms for the same promise. Layout-only alternatives can share the exact
approved headline and copy. Reuse
documented product truth and brand components; do not invent evidence to force
differences. No new offer, deadline, integration, pilot duration or metric exists
merely because a concept would look persuasive with one.

Preserve existing drafts. For an authorized multi-page native document, give each
page its own name/route and review it before moving to the next. Separate artifacts
follow the platform's normal preparation flow; never claim an artifact was created
from a plan alone or overwrite a previous draft to fake a collection.

At review, compare the actual rendered siblings with the direction rows. Identify
what evidence and visual decision made each page different, and which is strongest
for which reader. Review all requested pages at desktop/tablet/mobile and inspect
their real CTAs. If only one page is finished, report one finished page. A skill
read or successful render does not establish persuasive copy or visual quality.
