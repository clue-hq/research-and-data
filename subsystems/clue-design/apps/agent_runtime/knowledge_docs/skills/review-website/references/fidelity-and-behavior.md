# Fidelity, readability and behavior

## Source and final-state evidence

Use the actual brief, selected kit/source version, preserved properties and current
WebDoc context. `view("doc")` is only a section/count/asset summary, not a full
node snapshot. Read it with `view("brand")`, relevant
`view("cloned_section:<id>")` and actual asset pixels. `inspect_cloned_section(fragment_id)` supplies source
HTML/CSS/slots when exposed to the current role; source truncation is a gap, not
permission to reconstruct missing bytes from memory. The reviewer role may have
only view/provenance; ask the orchestrator for missing context instead of calling
an unavailable tool.

For a source match, compare the source and current section at matching viewport
and interaction states where supplied. Inspect composition, alignment, content
width, proportions, source spacing rhythm, responsive reorder/crop, type family,
weight, size, line height and hierarchy together. A flat, left-aligned substitute
for a centered image-led hero is a material fidelity failure even if colors match.
Do not introduce a universal line count, body size, spacing scale or column rule.
A captured font file does not prove it loaded; a root-unit or inherited-context
defect needs the source/runtime repair, not arbitrary per-element shrinking.

Separate original source content from transient consent/support overlays. Capture
admission, released library status and a screenshot comparison alone do not prove
source behavior survived. Frozen source captures evaluate capture; they do not
prove fresh onboarding, live library import, production generation or approval.
React-rendered WebDoc and sanitized captured HTML/CSS are not the source site's
original React component tree. Preserved CSS animations are not recovered JS or
WebGL. Name unsupported dependencies and states without claiming full fidelity.

## Read the page as an argument

At each width, identify the first read and what the next section contributes.
Headlines and their support should form a coherent message group. Heading and
body roles need a clear hierarchy; a prominent heading should not disappear
under larger support. One meaningful main heading and coherent nested semantics
matter; visual hierarchy need not be a rigid monotonically descending size list.
Compare density and scroll length with the real decision and source; repeated
text bands, unexplained mobile gaps and decorative repetition weaken the page.

The brand anchor needs a concrete expression in composition, type or imagery,
not just a matching palette. Apply the logo-off test to new or adapted sections
between their actual neighbors. If no concrete element expresses the anchor,
report "brand expression generic" and name the band; this is advisory unless
it also violates a source requirement or brief constraint. Where a supplied
Creative Brief states constraints, check each in pixels: a violation is a
reportable defect. Name the constraint, viewport and section id. User-requested
departures must be explicit. Geometry that materially violates requested source
fidelity is a requirement failure, not invariably an advisory nitpick. Smaller
optional polish can remain advisory.
Compare background rhythm and intentional color emphasis with the source/brief;
not every band alternates color, uses cards or shares an identical max-width.

## Responsive, imagery and identity checks

For every returned width, inspect horizontal overflow, collisions, clipping,
content order, text measure, image-to-copy balance and mobile navigation usability.
The clone walk can report `review.desktop_overflow` when measured content exceeds
its desktop wrapper. Inspect the named band and page boundary before repair:
contained intentional horizontal scrolling may be valid. An empty phone-overflow
result does not establish desktop health, and the clone walk does not measure
every newly composed section.
Read the actual support and closing copy at placement scale; enlarging a preview
to decipher it does not establish legibility. Trace the contrast chain: body and
muted text against their band or image/gradient, button label against its fill,
and logo against its band. An unreadable logo or text is blocking. Respect the
source's responsive composition; one column is not universally required.

Each image needs a message role and suitable crop, focal point, aspect and decoded
resolution for its rendered size/pixel density. A low-resolution avatar or photo
thumbnail stretched as hero is not a usable source simply because it loaded.
Inspect the full image and in-page crop. Asset metadata, URL width parameters and
a source label are not visual proof. Keep authentic source media, generated
derivatives and reference-only imagery distinct. Never substitute a generated
customer photo or redrawn product screenshot for a missing real one.

## Imagery — the decision check

Check the director's per-band imagery decision (real asset, generate, or deliberately
none with a reason) against what actually renders. Name the section when promised
imagery is missing. Flat placeholders and missing required media are failures.
A text-forward posture can be deliberate when the brief and composed content
support it. An unexplained bare stack of text bands is a finding; do not score
restraint as failure or bareness as restraint. Brand-generic imagery is advisory
unless it violates the source/request or fails to explain the adjacent claim.

A branded page shows the seller's real mark. No logo anywhere is blocking, not
advisory; a drawn or typeset stand-in for an available real logo is the same miss.
Use only the actual seller/target logo pixels and correct surface variant; wrong
company/program, incomplete required wordmark, poor contrast or missing requested
identity remains a gap. Omit optional empty account bands
cleanly; never leave stale example names, unresolved markers or half-populated
proof masquerading as personalization.

## Interaction and conversion

Review the states actually returned, with their width/node metadata:

- Dialog: trigger targets the real dialog, content fits, close control is usable,
  background remains stable. Missing target or content is a defect.
- Accordion/tabs: the opened or selected state exposes the intended real content
  without clipping, duplicate content or unusable labels.
- Navigation: closed/open mobile states preserve reachable readable links and
  desktop treatment follows the source, not a forced hamburger pattern.
- Carousel/marquee: controls and visible content work with the intended source
  affordance. A next-slide peek is optional; empty strips, overlaps or inaccessible
  essential content are not. Static screenshots do not prove pacing or playback.
- Embed/video: actual content/poster/fallback is usable at each affected width;
  missing-content placeholders and collapsed embeds remain defects. Test supplied
  reduced-motion behavior without assuming stored animation CSS means motion works.

State captures are bounded samples, not comprehensive interaction coverage. Check
keyboard focus/order/visibility, close/Escape behavior, tap targets and reduced
motion where the available browser evidence supports them; otherwise mark these
unverified. Do not infer keyboard accessibility, form delivery, all carousel
slides or all mobile tab states from one default screenshot.

For primary conversion, compare visible label, actual href/command/target and the
observed destination together. A booking label leading to the homepage is wrong
even if HTTP succeeds. A resource link needs the actual resource; an event needs
its actual registration/replay state. Repeated primary CTAs share the intended
action; their count/position follows the brief and source. Secondary trust/legal
navigation can be valid. Do not invent a form endpoint or claim a submission,
calendar booking, delivery or external publication that was not performed. Follow
existing authorization before submitting anything with external effects.

## Evidence and source coverage

Review target identity, seller ownership, relationship implications and all
factual copy against its source scope. Proof keeps owner/metric/comparison and
material conditions visible. Internal caveats such as unavailable links, missing
research or tool limits belong in the review summary; they are not buyer value.
A named concept without binding is not an account-derived page; a template alone
does not verify a requested batch. Follow `web-account-personalization` for
contact identity binding and appropriate allowed use.

For an account-content request, compare the argument in the current plan with
the rendered page: what supported account context changed the message, section
choice, proof or next decision? A role label or repeated company name alone does
not demonstrate researched relevance. Task-relevant proposals can be useful,
but do not accept them as deep account personalization when research was required
and unavailable. Keep internal research caveats out of visitor copy; removing
them must leave the remaining promises fully supported. An explicit identity-only
edit is reviewed at that narrower scope.

A missing source comparison prevents certifying required source fidelity. Report
what was observed, the available source/version and what remains unverified.
Neither a blank `broken_clones` array nor schema success overrides these judgments.
