# Scope, critique and honest final status

## Current callable contracts

Render, `review_cloned_page` and `finalize_web_run` belong to the orchestrator/solo
role. The independent reviewer has only `view` and `provenance`; it returns its
critique to the orchestrator rather than calling missing review/finalization tools.
The author finishes scoped writes and lets the orchestrator render and finalize.

- `render_web_preview()` has no width, selector or page-ID parameter. It renders
  the active page at 1440/768/375 plus a bounded set of supported state captures.
  A stale preview must be regenerated by the orchestrator/solo role; author and
  reviewer roles do not own the render tool. `unchanged: true` reuses current
  screenshots and permits reusing their still-applicable critique.
- `view(target)` accepts `doc`, `brand`, `account`, `preview:1440`, `preview:768`,
  `preview:375`, `state:<n>`, `asset:<id>`, `cloned_section:<id>`. It does not accept
  arbitrary file paths, a made-up source-comparison target or `node:<id>`.
  `doc` is only a section/count/asset summary, not full current node props/rich
  text or a persisted artifact version. Obtain actual current node snapshots
  through supplied context when available; otherwise report that read gap.
  If a report returns
  captures the current viewing surface cannot expose, record that limitation;
  the existence of the files is not inspection.
- `review_cloned_page()` returns measured `broken_clones`, advisory `page_findings`,
  capture/comparison material and observation gaps. It may write clone verdicts
  to the library. A zero-finding response does not certify aesthetics, all states,
  copy support or CTA destination. Nothing it returns alone blocks publication.
- `provenance(action="list")` exposes known sources/citations. `action="cite"`
  requires existing `source_ids_json` and `note`, with optional current
  `node_ids_json`. Unknown IDs are rejected; record any unsupported evidence
  binding in the current plan/report without fabricating a source registration.
- `finalize_web_run(outcome, summary, ladder_gap=None)` supports only `accepted`,
  `completed_with_warnings`, `failed`. It writes the current run result/document.
  There is no web `register_critique` tool or separate edit-only outcome here.
  Use `ladder_gap` only for an actual missing expressive capability; it does not
  make incomplete evidence or source custody disappear.

## Independent critique when available

If the harness exposes `lumen-web-reviewer`, pass the current brief/scope, source
and kit/version evidence, preserved requirements, final previews/states and known
gaps. Keep critique independent of an instruction to approve. It returns the
existing `VisualCritique`; pass repair feedback verbatim to the author and inspect
the renewed result. Do not add scene-only `direction_review` or invent a new
website schema. If the reviewer is quarantined/absent, self-review against the
same criteria and state that independence was unavailable. A text-only pressure
check of these skills is not this visual reviewer and cannot approve page quality.

The actual `VisualCritique` fields are `accepted`, `summary`, `issues`,
`repair_instruction`, `acceptance_notes`, `requirement_coverage_notes`,
`confidence`, and optional `reference_fidelity`. Each issue uses current
`severity`, `category`, `target` (page/node/slot), `message`, `suggested_repair`.
Describe viewport/state in the message. Use categories actually in the schema,
for example hierarchy, typography, contrast, imagery, asset_use, brand_fit,
request_satisfaction or tool_failure. Do not create an `account_grounding` enum.

## Decision and report

Acceptance is the reviewer's judgment for the stated scope, not new runtime
validation. Distinguish delivered artifact from verified quality:

- **Accepted:** the current requested result has been inspected, material
  requirements are met, and required source/evidence/conversion checks have no
  unresolved gap. State review scope. A scoped edit may be accepted as an edit;
  it does not certify unrelated pages or recover absent original-source behavior.
- **Completed with warnings:** a usable draft/change exists but a requirement or
  necessary check remains unresolved. Name the gap and what would resolve it.
  Missing required proof/logo/CTA, unobserved required behavior and material
  fidelity departures cannot be hidden behind a success summary.
- **Failed:** the requested artifact/change could not be produced or verified
  enough to hand off a usable result. Name the actual failing step and retained
  state; do not manufacture a preview or successful application.

Critical findings include overflow/clipping, unreadable text/logo contrast,
broken/missing required imagery, dead/misleading conversion, unusable navigation,
unsupported claims or identity, and a material unmet source/request requirement.
Advisory findings are optional improvements that do not invalidate the brief.
A high score cannot erase a specific unresolved requirement. Evidence gaps are
not observed pixel defects: say unverified instead of inventing a visual symptom.

Use a short final report: result and scope; actual changes; current evidence and
reviewer type; unresolved requirements/next repair; any library/template or
publication effects. Include the exact node/page and smallest coherent fix for
each actionable issue. Keep internal limitations out of visitor-facing content.
Do not claim publishing, live importing, account derivation or form submission
from artifact persistence alone.
