# Workflow contrast

Name the real user task and the specific change the product makes possible.
Ground factual steps in the supplied product/source context. Never invent elapsed
time, savings, integrations or a competitor's failures. An illustrative workflow
must be described as illustrative rather than presented as measured proof.

Choose a spatial relationship that makes the contrast understandable: sequence,
convergence, replacement or parallel comparison. Two equal panels and arrow rows
are options, not required structure. Let the most useful change dominate.

Build labels, connectors and simple geometry natively. Preserve authentic UI as
independent images if it helps. Do not ask the image model to rasterize the whole
diagram or fabricate a dashboard. Use fewer steps if reading order needs explanation.

Read `knowledge/scene/components.md`. Record both the supported contrast and the
native layer plan in the shared direction. At final placement size verify that
the sequence and its practical benefit are obvious without extra commentary.
