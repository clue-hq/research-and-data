# Roadmap v2 — post-Phase-4 (locked 2026-07-05)

Decision record from the roadmap discussion after Phase 4 (editor ladder 4a–4d) closed.
Grounding survey: export/brand-kit/slot state audited on `agents/editing-roundtrip-v0` this date.

## Facts that shaped the plan

- **Slotting already exists in the engine**: `crates/lumen-core/src/slots.rs` (content types incl.
  image/logo/repeater, bound_nodes, overflow policies, image fit/focal policy, editability), plus API
  binding sets / instance derivation / instance batches / template finalization. Scaling is
  productization + proof, not invention.
- **Brand-kit model already rich**: `TokenCatalog` (colors/typography/spacing/radii/shadows/aliases),
  `BrandAssets` (fonts w/ embed-subset license flags, logos w/ variants+clearspace, images),
  `BrandConstraints` incl. print rules, `approval_status`/`product_ready` on the kit row.
  Missing: the three ingestion paths + agent application of kit assets.
- **Print is half-done**: PDF export exists; bleed respected in the PDF page box; `pdf_intent`
  (Preview/Print) + `embed_fonts` already in the export profile — but font embedding is a stub
  (LUME0401) and there is no CMYK/ICC handling anywhere. Print = the print half of export hardening,
  not its own phase.
- **Agent-imagery gap is the keystone blocker**: plumbing browser-verified, but the agent loop does
  not yet reliably produce designs WITH imagery (see `image-agent-integration-gap` memory; LUMV0100
  generate-before-page crash, quality-loop author has no generate path).

## The locked sequence

**Main track (this workspace lineage, serial):**
1. **Phase 3 — imaging.** Close the agent-imagery gap first (agent composes with imagery reliably),
   then the human image-editing surface per MODA-EDITOR-PLAN Phase 3 (prompt-edit w/ Before-After
   accept gate, remove-bg; fit/focal stays the crop story).
2. **Moda restyle / Appearance slice** (token-value edit + section rearrangement) — also the
   consumption surface for ingested brand kits.
3. **Export & print hardening** — font embedding, CMYK/ICC + print intent, digital/print output
   config presets, bleed+imagery verification, DPI checks vs slot `min_dpi`. One phase, two profiles.
4. **Scaling / slotting productization** — slot toggle per node in inspector, content-schema ↔
   slot-key contract, instance derivation quality on real personalized content, batch export.

**Parallel track (separate Conductor workspace, API/Python-only to avoid collisions):**
- **Brand-kit ingestion v1** — three intake paths (web-scrape, brand-PDF, individual asset uploads)
  producing DRAFT kits a human approves (taste stays human-gated). Style inference maps onto the
  existing TokenCatalog; no new schema. Kickoff brief: `BRANDKIT-INGESTION-V1-BRIEF.md` (same dir).
- **Merge point:** agent APPLICATION of kit assets/theme in designs merges into the main track
  after Phase 3 (it needs the agent-imagery path; a kit logo is an image asset with brand metadata).

**Frontend revamp:** after the Moda restyle; may run parallel to export/print hardening
(engine/API-heavy, near-zero file overlap). Not parallel to Phase 3 or the restyle (editor-heavy).

**Content-schema:** deferred by user decision — no clarity yet on the content side; it will be
designed compatible with the existing slot endpoints when the time comes. A Seam-B discussion
draft v0 already exists (`.context/content-schema-contract/`, decisions D-1..D-6 open) — it stays
parked untouched until the user reopens it.
