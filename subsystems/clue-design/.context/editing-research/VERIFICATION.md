# Adversarial Verification of STUDY.md

**Verdict:** sound-with-corrections

## Net assessment
SAFE TO ACT ON, with two fixes before committing to the sequencing. The study's spine is correct and unusually well-grounded: the failure mechanism (solved-and-discarded positions, whole-tree relayout with no dirty tracking), scene-as-canonical (no dsl_source column, no scene->DSL emitter), the NodePatch field-addition pattern, the widen-out-of-flow-check seam (proven by a passing test), and the 'agent starts from empty, sees only an 80-node text summary' round-trip diagnosis are all verified against real code. The recommended architecture (Stance A spine + C container mode + B's base_anchor as one field, reject the override document and the DSL emitter) is feasible as described. FIX FIRST: (1) Phase 0 is NOT just a tools.py wiring change — it requires forcing continuation mode at the director/loop+prompts layer (new_artifact is a director decision in schemas.py/loop.py/prompts.py, not a tools.py method) AND changing the agent's authoring behavior to never re-author existing NodeIds (else LUMD0401 rejects the whole block on replay). That duplicate-id replay risk, which the study lists as 'validate first', is actually the gating work and is larger than the 'one wiring fix' framing implies. (2) The §5 claim that agent proposals 'trigger a wholesale replaceScene that discards human work' is imprecise — agent-apply uses applyOperations onto the live scene; the real loss vector is op-collision plus the post-preflight replaceScene(preflight.scene) at EditorApp.tsx:1099 swapping in a token-BAKED scene every turn, which deserves explicit handling. Everything else is citation drift, not substance. Recommend proceeding with the phased plan but re-scoping Phase 0 to include director-mode + no-reauthor-ids prompt work and a decision on the preflight->replaceScene token-baking path.

## Corrections (fold into the plan)
- FORBID-NEW_ARTIFACT CITATION (§5 fix #2, §6 Phase 0): The study says forbid 'new_artifact/start_fresh_rewrite_scene (tools.py:1498-1500)'. start_fresh_rewrite_scene IS a tool at tools.py:1498-1509, but new_artifact is NOT a tool there — it is an AgentActionMode enum value (schemas.py:161) chosen by the director (loop.py:87-88; gated in prompts.py:117,133). Correction: continuation mode must be enforced at the director/decision layer (loop.py + prompts.py), not only by disabling a tools.py method. This makes Phase 0 slightly larger than 'one line in tools.py'.
- AGENT-APPLY IS applyOperations, NOT replaceScene (§5): The study says agent proposals 'trigger a wholesale replaceScene that discards human work (EditorApp.tsx:521-549)'. The actual agent-apply path applyAgentProposal calls applyOperations(proposedOperations) (EditorApp.tsx:1028-1060 -> 1035 -> engine.applyOperations at 373-396), which applies ops onto the live scene. replaceScene at line 546 is the DSL-compile path and line 1099 is the post-preflight scene swap. Correction: the real Phase-0 risk is op-replay COLLISION (constructive insert_node with already-present ids -> op error/LUMD0401), plus the preflight replaceScene at 1099 swapping in a token-baked scene — not a wholesale discard at apply time. The study's own Phase-0 'validate replay collision' risk (§7.1) is the accurate framing; the §5 'wholesale replaceScene discards human work' wording is imprecise.
- MINOR CITATION DRIFT: (a) FinalizeTemplate non-invertibility is at operations.rs:1222, not within the cited 1019-1030 range (that range is the InsertNode case). (b) The 'universal mutator at operations.rs:102-126,158' conflates the NodePatch struct (102-126) with the Operation::UpdateNode variant (158); the actual mutator BODY (update_node) is at 556-597. Mechanism is correct; line refs are loose.
- LayoutMode/AutoLayoutProps GRAFT (§3.1): The study proposes adding layout_mode to AutoLayoutProps (scene.rs:470-497). Note AutoLayoutProps is the per-Node `layout: Option<AutoLayoutProps>` field (scene.rs:292, default None), distinct from NodeKind::AutoLayout(AutoLayoutNode) (scene.rs:333,448-451) which carries direction/wrap and is what layout_node_at branches on (layout.rs:160-161). A Free-container branch in layout_node_at must key off the node KIND being AutoLayout AND read layout_mode from the layout props — the study's 'branch the kind-switch at layout.rs:157-169' is correct but the field lives on Node.layout, not on the AutoLayoutNode kind; implementers should not confuse the two structs.

## Caveats / unverified claims
- NodeId STABILITY ACROSS HUMAN EDITS (§7.3, flagged by the study as a risk, not asserted as fact): I could not confirm the editor's id-allocation reuses ids on human delete+recreate. NodeId::from(&str) and From<String> (ids.rs:60-70) BYPASS validate_stable_id (only ::new() validates), so ids are whatever the producer supplies. The study correctly lists this as a 'validate first' item rather than claiming stability — appropriate, but it remains genuinely unverified in this codebase pass.
- 'base_anchor lets the agent preserve a 12px offset after relayout' (§2,§3.1,§5) is an architectural proposal, not an existing behavior — there is no diff-against-base_anchor logic anywhere today (the field does not exist). The study presents it as a design recommendation, which is fine, but no code supports any reconciliation semantics yet; it is entirely net-new agent logic whose cost the study under-weights relative to its '5% of B's cost' claim.
- 'compile_dsl_into_scene applies additively so the machinery downstream already works' for SEEDING (§5 fix #1): additive DSL compile is confirmed, but seeding self.scene from payload.scene is a JSON->Scene parse in the Python/core boundary (core.py path), which I did not fully trace end-to-end (core.py:86 was cited but not read this pass). The claim that 'the core tool already accepts an arbitrary input scene' is plausible from new_scene's existence but the specific deserialize-and-mutate path for a human-modified scene with NEW fields was not verified.

## Gaps the study missed
- DUPLICATE-ID REPLAY is the single biggest unmodeled risk. Once seeded (Phase 0), if the agent regenerates ANY node id that already exists in the seed, DSL compile hard-errors LUMD0401 (dsl.rs:704-715) and the whole block is rejected (dsl.rs:69-76). The study mentions collision as a 'validate first' item but does not state that the agent's authoring prompts/DSL generation must be changed to ONLY emit `modify #id` / structured UpdateNode against existing ids and NEVER re-author existing ids — that is a prompt+loop behavioral change, arguably larger than the wiring change, and is the actual gating work for the round-trip.
- PREFLIGHT TOKEN-BAKING ON THE ROUND-TRIP: preflight resolves tokens by baking literals and nulling *_token on a clone (brand.rs, preflight.rs:145,160). But EditorApp.tsx:1099 does replaceScene(preflight.scene) after applying an agent proposal — meaning the LIVE editor scene can be replaced by a token-BAKED scene post-agent-turn. The study treats token loss as only a raw-edit-style hazard (§5), but this preflight->replaceScene path could strip live token bindings on every agent turn that triggers export preview, degrading future re-theming independent of any human raw edit. Not addressed.
- EDITOR vs CANONICAL LAYOUT PARITY for frozen boxes: the editor relayout uses an injected/heuristic measurer (engine.rs:130-133, FALLBACK_MEASURER at layout.rs:64) while the server injects a Skia ProvidedTextMeasurer. The study flags this (§7) but understates it: DetachToFreehand reads computed.layout_bounds to seed absolute_box, and if that read happens in the EDITOR (heuristic) rather than from a canonical pass, a frozen text box can be subtly wrong on export. The study says 'bake from the canonical layout pass' but the editor is where the detach gesture lives — bridging that requires a server round-trip at detach time or shipping the Skia measurer to the client, neither of which is scoped.
- VALIDATION OF DETACH AGAINST node_can_have_children / leaf constraints: update_node rejects turning a node into a leaf while it has children (operations.rs:568-576). Detach/convert composites must respect this and the cycle check in move_node (operations.rs:518-525). Minor, but the composite-builder design in §3.3 does not mention these guards.
- MULTI-PAGE / page-child detach: layout_pages lays page children at origin = child.transform (layout.rs:141-145). A page-direct child is already 'absolute' (it drags today). The study's Phase 0 claim that this already round-trips is plausible, but absolute_box semantics for a node whose ancestor is the PAGE (not an auto_layout) overlap with the existing transform-based positioning — the model now has TWO ways to express absolute position (transform.x/y for page/frame children vs absolute_box for detached auto-layout children), and the study does not specify how render_box_for_node / the inspector disambiguate which is authoritative when both could be set.

## Confirmed claims (spine is sound)
- FAILURE MECHANISM (§1): layout.rs:157-169 dispatches purely on parent kind (matches!(node.kind, NodeKind::AutoLayout)); auto-layout children get Taffy-solved positions via collect_taffy_geometry (layout.rs:322-330, origin = parent_origin + layout.location), and the authored transform.x/y is never passed into the Taffy Style for in-flow children. Frame/Group/Page children are honored at origin + child.transform.x/y (layout.rs:179-192, 340-373). Confirmed.
- RELAYOUT CLOBBER (§1): WasmEngine.relayout (crates/lumen-wasm/src/engine.rs:129-140) runs a whole-tree layout_scene and writes node.computed for every returned node with NO dirty/incremental tracking, so a human transform write is re-solved away. editing.rs:1002-1006 clears computed (OptionalFieldPatch::Clear) on render-affecting patches. Confirmed.
- OUT-OF-FLOW SEAM (§1): is_out_of_flow_transform (layout.rs:1508-1512) returns true on nonzero rotation/skew; such a child is `continue`-skipped from the Taffy children list and emits LUMV0701 (layout.rs:264-280), then is laid out at origin + child.transform in the by_lumen-absent branch (layout.rs:340-357). The passing test layout_engine.rs:766-789 proves a rotated child keeps transform.x=100 while sibling stays at flow x=40. Confirmed — this is a real seam to widen.
- EDITOR GATE: isNodeLayoutManaged true iff direct parent kind === 'auto_layout' (sceneQueries.ts:172-181); isNodeDirectGeometryEditable = !locked && !layoutManaged (sceneQueries.ts:183-192); canvas drag/resize early-return null when not editable (canvasOperations.ts:41,77); inspector X/Y/W/H disabled via !directGeometryEditable (InspectorPanel.tsx:248-279). Confirmed.
- SCENE IS CANONICAL: migrations/001_init.sql stores documents.current_scene_json (line 6) + operation_log with source CHECK in ('editor','agent','api','system'); 003_edit_envelopes.sql carries operations_json + inverse_operations_json. There is NO dsl_source column in any migration. Confirmed.
- NO SCENE->DSL EMITTER: grep for to_dsl/emit_dsl/scene_to_dsl returns zero across crates/ and apps/; the only matches for 'dsl_source' are schemas.py:289 and loop.py:292, which carry agent-AUTHORED DSL text (not a scene serializer). The only serialize path is scene_json() at lumen-wasm/src/engine.rs:175-177. Confirmed.
- DSL IS ADDITIVE/CREATE-ONLY: compile_dsl_into_scene(source, scene: &mut Scene) applies onto an existing scene via apply_operations_checked (dsl.rs:54-95); LUMD0401 hard-errors on duplicate node id when authoring (dsl.rs:704-715); `modify #id` resolves by NodeId against the live scene and reads current state, erroring LUMD0901 if missing (node_edit_patch_from_properties, dsl.rs:2310-2348).
