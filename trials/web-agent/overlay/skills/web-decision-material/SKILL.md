# Give the buyer something useful to examine

For a page for one named account, `account-page-copy` decides the message and the
sections. Use this skill there only when its message plan calls for an exhibit, and
start that exhibit from a cloned section, as `account-page-copy` §4 says; its reuse
order wins over the container rule below.

Research is an input to an argument, not the page's prose. Use
`web-account-personalization` for evidence/identity and `conversion-copywriting`
for supported wording. This skill turns that argument into concrete page material.
Read [worked decision exhibit](references/worked-exhibit.md).

## Write before choosing the container

In the existing plan, select the strongest relevant account priority. Name the
reader's practical question, the supported seller mechanism and the real product
evidence available. Write the explanation and exhibit BEFORE filling clone slots.
Then select the source component that can carry them. A shortage of slots is not
a reason to remove the substance or shrink the type.

Choose an exhibit by the reader's question:

| Question | Useful material |
| --- | --- |
| How would the work change? | A proposed task walkthrough: trigger, product action, person/system handoff and what the reader can inspect. |
| Can this meet our criterion? | Criterion → documented mechanism → genuine product state or relevant proof → question to resolve. Write the actual entries, not those labels as public headings. |
| What should our team evaluate? | A short evaluation worksheet with scenarios, observations and unresolved dependencies; no invented baseline, promised outcome or seller pilot commitment. |
| Is there credible evidence? | A relevant, attributed customer example or authentic product demonstration. Another customer's result is not the target's forecast. |

Connect the exhibit to the account in a concise introduction, then explain the
mechanism in ordinary work language. Add related resources only when held, relevant
and useful. The result should answer a question, not just contain more text/cards.

**Explain before asking the reader to evaluate.** Supply a concrete worked
application: what happens, what the product shows/does, and why that matters for
the evidenced priority. An evaluation worksheet is an optional later aid, not
the default content for every page. A page made entirely of “review,” “assess” and
questions hands the explanatory work back to the visitor. Its headline should
express the supported useful proposition, not the agent's task of evaluating it.
Distinguish an illustrative scenario from the account's actual operations without
filling the page with research caveats.

## Build a coherent page

Read the headings in sequence: the opening explains the useful proposition; the
next material demonstrates it; subsequent material resolves a decision; the action
matches that decision. This is a reasoning sequence, not a required section order
or count. Reuse strong source surfaces with `create-website`; use
`web-product-story` when a demonstration carries the explanation.

Before building, apply two checks:

- **Substitution:** if another account's name fits without changing the exhibit,
  identify which evidenced priority is missing. Do not invent specificity to pass.
- **Utility:** can the reader describe the product action and something they can
  now assess? Feature labels, a biography and decorative screenshots alone fail.

For sparse evidence, create a useful role/task-level draft and report its limits
internally. Keep analyst caveats, verification mechanics and speculative motives
out of visitor copy; retain material product limitations. Select the actual next
action through `campaign-landing-page`, not a default demo.
