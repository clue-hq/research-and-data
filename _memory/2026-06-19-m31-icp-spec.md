## Key decisions
- Enriched the SHARED `core.ICPSpec` (one object M3.2/M3.4 read), not a separate icp record — matches
  the spec's "single object" + conventions §4 "Versioned ICP spec". Lifecycle on the contract.
- Append-only enforced at DB level (trigger), same discipline as M1 claim — "active spec immutable".
- Opaque slots (discovery/source_profile_ref/scoring_rubric) stored as JSONB dicts; M3.1 never
  interprets them (out of scope per spec).
- `create_icp_spec` is the single append path (works for first version AND edits); `parent_version` =
  prior max version (linear lineage); `activate=True` archives prior active first (avoids the partial
  unique index conflict).
