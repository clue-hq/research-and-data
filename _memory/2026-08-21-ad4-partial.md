## The one pattern that dominated the phase

**Every single sub-slice shipped at least one defect of the same shape, and green tests never caught
one of them. The browser caught all of them.**

> *A control displays or commits a value the document does not have — or a legitimate edit is silently
> swallowed.*

Instances, in order: the Custom W/H boxes seeded from a fabricated 1200; per-keystroke page writes
persisting a 1×1920 page; the Custom boxes going stale after a preset write; the canvas panel showing
"Story" while the document stayed square (a whole selection state that could not write at all);
Solid→gradient discarding the colour just set; gradient→Solid writing nothing while three surfaces
disagreed on one screen; a token-filled text swatch showing the dummy's `#00F59B`; a kitless document
offering six invented swatches and committing one for real; the radius scan button clobbering three of
four corners; the corner fields refusing to accept a legitimate re-type (which made restoring the
document through the UI *impossible*); the mirror re-stating five boxes over a locked node the write
refused; an upload minting a server-side asset on a read-only editor and saying nothing.

The cause is structural, and worth carrying into Lane B/C/D/E: **§4 forbids remounting the inspector on
a write token**, so a control that displays a value re-reads it only on remount. That is correct when
the stale value is what the user just typed, and wrong the moment a *sibling* control, or a refusal,
moves the document underneath it. Three disciplines fell out of it and now bind every row:

1. a numeric field commits on **blur/Enter**, never per keystroke;
2. **a write that changes nothing is not a write** (compare against what the node holds, return null);
3. **a local "committed" snapshot must hold what the write produced, in the write's own spelling** —
   and must not move when the write was refused.

## For the founder — five items, none blocking

1. **A page-size change does not reflow the ad.** Pick "Story (9:16)" on the square ad and the artboard
   becomes 1080×1920 while the content stays 1200×1200 — overflowing right, blank below. This is exact
   upstream parity and §1.1 says only "writes `update_page`". Screenshot `/tmp/ad40-s1-b-story-preset.png`.
2. **The disabled-state premise may be false, and if so it closes a whole family.** Several rulings —
   AD3.1's refuse-rather-than-flatten and the deferred A19 — rest on "our inspector has no disabled
   state". Established this session: `ColorControl`'s `disabled` is a *value* state (a red-slash swatch
   and the word "None") and its CSS actively cancels the disabled look; `InspectorInput`/
   `InspectorSelect`/`InspectorField`/`RadiusControls` have no `disabled` prop at all. **But one real
   disabled treatment exists** — `.backgroundGradientRemove/Add:disabled { opacity: 0.45 }`. So
   upstream's `disabled={selectedNode.locked}` posture is not technically blocked; it needs visual
   design for fields. If granted, the A19 family closes at its root.
3. **§1.0's Lock row has no surface on the canvas schema** — the artboard cannot be locked or unlocked
   from the panel (the dummy's own composition; writes still honour a lock set elsewhere).
4. **A23 is presentation-visible**: a document with no brand kit now shows an empty Theme tab instead of
   six placeholder colours. Custom stays fully functional.
5. **Two labels are wrong and relabelling is founder copy**: the picker's "Recent colors" strip has never
   shown recent colours, and an unresolvable asset digest still falls back to a stock photograph over a
   real ad node (the web lane has the identical fallback, so one ruling covers both).

## Addendum — AD4.A step 3 (the AI image suite) shipped, 2026-08-21

Four more commits, `3e1e4960..7bca24d3`. **Lane A is now complete** (steps 1, 2, 3, 4). Frontend only.
Gate at close: **1750/1750**, lint 0 errors, build green, `tsc --noEmit` unchanged at 84.

**What it is.** The MVP editor's image AI suite, composed into the ad inspector: Alt text · Generate
from a prompt · Edit by instruction · Remove background · Before/After candidate review with
Accept / Reject / Save-as-new · asset status line. All of it inside the existing **Fill** section.

**Why it was the phase's riskiest slice, and how that was handled.** The dummy designed *none* of this.
Every other slice bound controls that already existed. So the brief carried a **ranked composition
rule** — existing primitive > existing class in its own role > a borrowed class with the borrow
justified in writing > STOP and report a blocker — and forbade new CSS, new icons and new copy. The
implementer enumerated first and **stopped to ask**, which is what made it work.

Its finding settled the question: **the inspector has no labelled action button at all**
(`.inspectorActionGrid` is a 27px transparent *icon* grid with only 4- and 6-column templates). So
three borrows were approved: `.sharePrimaryButtonWide` / `.shareSecondaryButton` from the share menu —
the primary carries **the shell's only authored `:disabled` treatment**, needed three times here and
un-inventable under A19 — and `.imageReplaceField` for the review tiles. Text-only labels, no lucide.
That "no invented CSS" rule is now **mechanical**: a test asserts the AI components' class set equals
exactly the five justified classes, so authoring *and* using a new one fails the build.

**Rulings (continuing the ledger's numbering):**
- **A35** — the button borrow, approved on the `:disabled` argument.
- **A36** — **both** review tiles, "Before" and "After". I overruled the implementer's leaner one-tile
  option: the contract row names the comparison, and a comparison whose halves are separated by two
  form fields is a candidate preview next to a coincidence. Browser-vindicated — at ~116px the two
  tiles read fine and the difference is immediate.
- **A37** — the status line renders only when it says something the panel does not (`No image yet`;
  `Asset <id> · <status>` when not ready); silent on a ready asset. Trimming upstream's
  "…or place one from the asset library" clause is amendment 4's own precedent — that clause names a
  surface the platform does not have, and instructions that cannot be followed are not copy.
- **A38** — **all placement paths carry a stored `alt_text` forward**, falling back to the record label
  only when absent. This deliberately changed step 2's shipped Replace-image row: once this slice ships
  an Alt text control, alt text is user-authored accessibility content, and overwriting it with a
  filename on the next swap is this lane's signature defect in its most damaging form.
- **A39 (the blocker)** — a generate resolving after the artifact tab changed could **write into a
  different ad**. The post-await re-read compared only the node id while the slice's own `accept` path
  compared node id *and* document id and carried the comment saying why. Harvested node ids are
  template slugs, so the collision is not exotic.
- **A40** — the candidate review moved **out** of the `canEdit` block. `canEdit` folds in the lock, so
  locking a node while a candidate was staged used to erase a paid Before/After review with nothing
  explaining it. Upstream renders it as a sibling for exactly this reason.
- **A41** — the same cross-document guard was fixed in the **website lane's** `use-replace-image.ts`.
  A cross-document write is data integrity, and "another lane owns it" is not a reason to knowingly
  ship one. The alt-text overwrite there was deliberately *left* — that is a behaviour preference on a
  surface this session did not review, and it is recorded with A38's argument for whoever picks it up.
  The mechanism was worse than first framed: `applyOps` is a `useCallback` bound to its `documentId`
  while `baseVersionRef` is live, so a late upload posts to the *old* document id keyed on the *new*
  document's base version — a CAS-key mismatch, not merely a misdirected write.

**Browser-proven end to end**, on the live stack against the real design API (`/assets/generate` works
in this environment; I verified it before dispatch and it minted a real asset): remove-background
staged a candidate **without touching the document**, and the After tile showed genuine transparency;
Accept swapped the asset while `alt_text`, `fit` and `focal_point` all rode forward; Generate swapped
immediately with **no** candidate step and carried the user's alt text forward; Reject changed nothing;
alt text wrote exactly one version on Enter and none while typing; the status line stayed silent on a
ready asset; and after A40, locking a node left the staged review intact. Screenshots:
`/tmp/ad4a-s3-{a-suite,b-edit-block,c-candidate,d-accepted,e-generated,f-locked-review}.png`.

**The pattern held to the end.** The review found the blocker; the *re-review* then found a regression
the blocker's own fix introduced (a refused Accept wiping the typed instruction). The implementer's
closing note is the lesson: its R4 said "a refused Accept keeps the candidate" — true but incomplete.
It should have said **a refused Accept changes nothing the panel holds, the draft included.**
