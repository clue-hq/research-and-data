## Key design decision: NO new migration
The rubric is stored in the **existing `icp_spec.scoring_rubric` JSONB slot** (M3.1 already created
that column). So M3.4 adds **no alembic migration and no claim-store schema change** (matches
ENG-121 "No claim-store schema changes"). Append-only versioning *is* M3.1's icp_spec versioning:
editing weights → `create_icp_spec(...)` writes a new ICP-spec version carrying the new rubric; a
campaign pinned to `(client_id, icp_key, version)` re-reads — and re-scores — identically. Single
alembic head stays **0011**.

## Adversarial review (Workflow find→verify, 5 dims) — 13 raw → 9 confirmed, ALL fixed
Production hardening (2 real defects):
1. `inf` weight passed `Ge(0.0)` → normalization `inf/inf = NaN` silently. Fix: `Weight =
   Annotated[float, Ge(0.0), Field(allow_inf_nan=False)]` (mirrors UnitInterval's Le(1.0)).
2. `_clamp_unit(nan)` returned NaN → `score()` raised on a NaN value/param, contradicting the
   "degrade to 0.0, never raise" contract. Fix: `_as_float` now rejects non-finite (`math.isfinite`),
   so nan/inf values+params degrade to 0.0 factor and `score()` stays total.
Test-coverage (7): DB-free `validate_rubric` test (AC4 now in the always-run gate, not DB-only);
slot-roundtrip now re-scores the round-tripped rubric (AC7 through serialization); STALE/LOW_CONF/
MISSING projection onto core Score; `as_intent_score` + zero-total-weight no-ZeroDivisionError;
min_confidence boundary (strict <); flag precedence (MISSING > STALE > LOW_CONFIDENCE); CATEGORICAL
non-string/str-coercion + bool-is-not-a-number + non-finite transform rows.
