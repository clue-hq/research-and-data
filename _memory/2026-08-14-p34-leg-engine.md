## Decisions taken in-slice (not in the spec's words, ratified by the spec's principles)

1. **Inline lane, not a queue hop.** D3 says design-leg turns "execute on the design_job fleet
   lane". Implemented as `design_fleet.InlineDesignLaneDriver`: the AGENT_TURN worker drives the
   REAL `DesignJobWorkHandler` inline under a real `work_lease` on the run's work id — same claim
   CAS, same generation fences, same run-event stream; only the queue round-trip is skipped.
   Reason (structural): `LeasedWorkWorker.drain_once` runs ONE task at a time per process, so an
   AGENT_TURN handler that enqueued a `design_job` and awaited it would deadlock every
   single-worker deployment against itself. Single-flight per thread is preserved for free (the
   AGENT_TURN task stays live exactly as long as the design turn runs).
2. **The design turn's terminal shape is a real committed finalization.** Success = an
   `AgentFinalizeEnvelope(status=AWAITING_INPUT, open_gate_refs=(design_leg ref,))` recorded via
   `record_finalization` + `commit_finalization_authority` — which buys the lane-D committed-
   outcome replay short-circuit with zero new machinery. Failure = `mark_unfinalized`
   (`design_leg_turn_failed`), NO manufactured finalize, leg stays open. A retried failed turn
   converges through the derived design-run id (terminal run row = re-join, never re-run).
3. **No platform workspace lease for design turns.** The design runtime's virtual workspace is
   keyed to its run; `agent_turn.workspace_root_id` records `design-leg:<leg_id>`. Acquiring a
   platform file workspace for a turn that materializes nothing would be fabricated attribution.
4. **Envelope config contract** (platform-authored; design-side consumption is P3.5/P3.7 work):
   `config.request` (AgentTurnPreviewRequest-compatible: prompt, scene from the stored document,
   document_id, previous_turn_outcome), `config.delegation_bundle` (§2.3 bundle by value),
   `config.history` ([{role,text}] — prior leg exchanges), `config.leg` (leg_id, thread_id,
   agent_turn_id, execution_id, pins, focus_refs). The design harness does not read
   bundle/history/leg yet — adopting them design-side is the P3.5+/Part-IV half.
5. **Leg history join is by turn parentage** (`agent_turn.role='design' AND
   parent_execution_id = leg.parent_execution_id`), not by `design_agent_run.leg_id` — so a turn
   whose run never got created (crash before dispatch) still belongs to its leg, and a reopened
   leg resumes its history (same parent execution). The head-of-abm load excludes by role
   (`role <> 'design'`), not by leg: it never sees ANY design transcript.
6. **Bundle byte cap = 24_000** (half the 48k L3 layer; utf8-bytes counter — the C8 card
   legitimately takes the other half). Claim refs validated at the input model via
   `ContactHandoffClaimRef` (existence/governance provenance stays with the research-view tools
   that produced the ids).
7. **`open_design_leg` replay-on-closed refuses** (`design_leg_replay_closed`): the mis-exit
   reopen is P3.5's re-delegation contract, not a silent side effect of the entry tool.
8. **Stream projection for design turns**: `turn_started` → `rehydrate("design_turn_summary")`
   → `turn_finished(awaiting_input)`. No platform text streaming (design progress rides the
   design_run subject per D3); leg lifecycle events on the chat stream are P3.7 (delta 8).
