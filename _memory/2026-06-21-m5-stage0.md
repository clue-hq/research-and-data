### Key design decisions (verified against the real M1–M4 APIs, not assumed)
- **Version ledger is claim-native — NO new table** (Beat-0 says M5 adds none). A `client.kb_version`
  marker claim carries `{version, run_id, ...}`; a new run bumps version + supersedes the prior
  marker; re-entry with the SAME run_id reuses it (idempotent). Prior versions stay queryable
  (append-only). `read_client_kb(version=N)` pins by filtering claims to that version's run_id.
- **client.* is tenant_private** via the stage0-local reuse policy (passed into `resolve_field`'s
  `reuse_policy` arg + `stamp_reuse` for direct writes), NOT by mutating M2's shared default.
- **No planner/ICPSpec at reverse-profiling time** (it runs pre-ICP): drive `sources.resolve_field`
  per field using the field's registered `tier_plan` (tiers 1–3). The Source Planner needs an
  ICPSpec, which doesn't exist yet — the field tier_plan IS the client-KB source profile.
- **stage0 cannot import resolvers/adapters** (import-linter one-way seam, confirmed in pyproject).
  So the live Firecrawl/CRM client-knowledge extractor + `register_scrape_resolver` wiring is
  api-composition-root integration; the orchestration is tested by binding fakes via
  `sources.bind_resolver` to real seeded source_keys (firecrawl_site tier-2). `_finalize` asserts
  claim tier == manifest tier, so fakes bound to firecrawl_site return tier-2 claims.
- **Tier-4 client synthesis is out of scope (M11)**; M5.1 only provides the judge-gating hook
  `_judge_tier4_claims` (calls the injected `core.FaithfulnessJudge`). Default pass is tiers 1–3.
- Client resolved deterministically (domain) — reuse existing survivor or insert a fresh ACTIVE
  entity; the client is authoritative about itself, never routed through the fuzzy review queue.

### Environment / DB note (IMPORTANT for parallel branches)
- `localhost:5432` is a **Homebrew Postgres 17.9**, NOT the docker `clue-postgres` container. Per the
  parallelisation gotcha, M5 uses its **own** database `clue_m5` (created on the brew server;
  migrated to head `eab62cbb1366`). Run DB tests with
  `CLUE_DATABASE_URL=postgresql+asyncpg://clue:clue@localhost:5432/clue_m5`.
- The `claim` table is **append-only** — DELETE is blocked by a trigger (erasure is M10.5). So
  DB-committing tests (the handler) can't clean up by delete; use a unique tenant+domain per run
  → fresh entity at version 1.

### Lessons / gotchas
- **Do NOT auto-reflow docstrings with a script.** A tokenize-based reflow dropped the leading indent
  on function/class docstring opening lines (the `"""` token excludes its indent) → IndentationError.
  Hand-wrap long docstring/comment lines to ≤100. Comment-block reflow was fine; docstring reflow was
  the trap. Lost time recovering.
