## KEY DECISIONS / mechanics
- The engine stamps the provenance the resolver can't know: `source_key`, `run_id`,
  `research_mode`; and for CONTACT claims `identity_binding` from the manifest (authoritative).
  `_finalize` does `model_copy` then re-validates (model_copy doesn't validate).
- `_finalize` asserts `claim.source_tier == manifest.tier` (fail loud — a lying resolver would
  corrupt the merge trust order).
- **Idempotency keyed on `(entity, field, source_key, run_id)`** (NOT tier — a tier_plan may list
  >1 source at one tier; tier-keying mis-attributes on retry). A retried step is reused (no
  re-resolve / re-write). The idempotency reuse check runs BEFORE the budget gate (reuse spends
  nothing → must never be budget-blocked); reused cost still folds into spend for later steps.
- stop_reason fall-through: `TIER_EXHAUSTED if ran_any else NO_RESOLVER` (all-inactive / empty /
  unregistered / only-unbound → no_resolver — a correct flagged-empty).
- Budget pre-check uses the manifest `cost_cents` as the pre-spend estimate; `total_cost_cents` is
  actual claim cost. Per-step `resolve.<source_key>` trace spans (cost + best_confidence).
