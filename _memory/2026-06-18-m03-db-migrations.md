## Key decisions
- **Driver/engine:** SQLAlchemy 2.0 async Core engine over **asyncpg** (`postgresql+asyncpg://`).
  No ORM models in M0.3 (domain tables are M1) — engine/pool + Core `text()` only. `pgvector` dep
  installed for the eventual `vector` SQLAlchemy column type (not used yet; extension enabled via SQL).
- **Async pattern:** one process-wide engine owned by `db_lifespan()` (`@asynccontextmanager`, the
  FastAPI-`lifespan` shape built on stdlib `contextlib` — NO FastAPI dep). `get_engine()`/`get_pool()`
  return the live engine (pool owner) and RAISE if no lifespan active (ownership stays in the lifespan).
  `connection()` = pooled conn; `transaction()` = conn-in-txn (commit/rollback). Dispose on exit closes
  all pooled conns -> no leaks.
- **DSN seam = `CLUE_DATABASE_URL`** read via `os.environ` in `db.engine.database_url()`. `db/` does
  NOT import `clue_research.config` (parallel agent owns it) — env var is the contract. Local default
  `postgresql+asyncpg://clue:clue@localhost:5432/clue` (matches docker-compose). alembic/env.py reuses
  `db.database_url()` so engine + migrations never disagree; `sqlalchemy.url` left blank in alembic.ini.
- **value_json:** NOT re-implemented — callers use `core.serialize_value_json`/`parse_value_json`
  (M0.2). No engine-level JSON codec registered.
- **Migrations:** Alembic async (env.py runs `asyncio.run` -> engine.connect -> `run_sync`).
  `target_metadata=None` (autogenerate effectively off — hand-reviewed). Numbering `NNNN_<slug>.py`
  zero-padded sequential; `file_template=%(rev)s_%(slug)s`; `timezone=UTC`. Initial migration
  `0001_enable_pgvector.py`: up = `CREATE EXTENSION IF NOT EXISTS vector`, down = `DROP EXTENSION IF
  EXISTS vector`. NO domain tables.
- **Make targets** (appended): `db-up` (compose up --wait), `db-down` (down -v), `migrate` (upgrade
  head), `migrate-down` (downgrade -1), `db-smoke` (upgrade head -> downgrade base -> upgrade head).
  compose uses `pgvector/pgvector:pg16`, port 5432, healthcheck `pg_isready`, named volume.
- **Tests** under `tests/db/` (own `conftest.py` with the `require_db` gate + `run_async` helper; a
  `tests/db/__init__.py` so relative imports resolve). DB tests `pytest.skip` when `CLUE_DATABASE_URL`
  unset OR DB unreachable (probe = connect + `SELECT 1`). No `pytest-asyncio` added (constraint: only
  the 4 named deps to [project.dependencies]); async driven by `asyncio.run()` in sync bodies.
  Files: test_db_engine (DSN read + accessor-raises + lifespan no-leak + txn commit/rollback),
  test_db_pgvector (CREATE EXTENSION + throwaway vector(3) col insert + `<->` distance query),
  test_db_migrations (up/down/up via alembic command API + census = only `alembic_version`, no domain
  tables, + downgrade drops `vector`).
