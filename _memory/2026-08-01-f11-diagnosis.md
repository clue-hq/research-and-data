## Verdict: NEEDS_CONTEXT (founder decision required)

The F11 hypothesis ("the live composition never invokes the Sumble resolver leg the fixture e2e

## Root cause

Confirmed ICP `us_independent_neurosurgery_spine_practices` v1 (ws `s0-trial-acceptance-aura-c2-…`):

- `field_keys` = healthcare.npi + 6 deep/contact fields. **`core.employee_count` is not in the
  compiled field plan at all** (plan = `spec.field_keys ∪ pack fields`; the `healthcare_practice`
  pack registers only `healthcare.npi`).
- `scoring_rubric.fit` = one entry, `healthcare.npi`, boolean, weight 100. `pass_a_fill_fields`
  narrows Pass A to `rubric.field_keys` (D7), so `fill_fields == [healthcare.npi]`.
- `healthcare.npi.tier_plan = ["npi", "cms"]`. Both are registered `source_manifest` rows but have
  **no bound resolver** in a Sumble-only trial (`ClueTrialSpine.__init__` clears bindings and
  registers only the 3 Sumble resolvers).

Proof the waterfall ran and was honest: `source_yield` for the scoring run has exactly two rows —
`npi` and `cms`, 0 claims / 0 fields / 0 cost. `sumble_organizations` was never attempted. The fit
claim records `components[0] = {name: healthcare.npi, value: 0.0, evidence_claim_ids: []}` with
`missing_value_rule: zero` → `fit = 0.0`. Correct arithmetic over nothing.

Proof nothing is lost downstream: the archived org receipt (2 credits, employee_count 488) run
through the production `normalize_organization` offline yields `core.employee_count = 488` with
evidence span + sumble source url, and `core.primary_domain = oregonclinic.com`. The claim would
appear at **zero** marginal cost the moment a field plan asked for it.

## Why nothing was "fixed"

Every candidate closes it by changing policy or governed data, not a wire: (A) have acquisition
write its paid attributes regardless of the rubric — contradicts D7 *and* the fixture e2e's
`assert "core.primary_domain" not in by_field`, and still leaves fit 0.0; (B) author ICP v2 —
rewrites a human-confirmed artifact; (C) source-aware ICP synthesis — new Stage-0 behaviour;
(D) register an `npi` resolver — breaks Sumble-only; (E) loud zero-coverage warning in SCORING —
worth doing but writes no claims and does not open the gate.

## The real finding

**A Sumble-only trial cannot serve a healthcare-practice ICP.** The ICP's deterministic hook is a
medical registry (its own proposal ranks `npi`/`cms`/`google_places`/`job_boards`/`journals` as
source priors — none is Sumble, and three are not registered sources at all). The corpus compounds
it: The Oregon Clinic has honest-empty engineering jobs and tech stack was skipped, so the only
Sumble facts available are employee_count + domain, neither of which the ICP scores on.

Recommended: re-run the canary against an ICP + account Sumble can actually serve (a `data_infra` /
tech-company ICP whose rubric weights `core.employee_count`, optionally `core.primary_tech_stack`
with the unbounded-tech approval). No code change; it is the honest "is Sumble worth it before Exa"
test T6 exists to answer. Then (separately) decide C and E.
