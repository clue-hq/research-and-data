## Key design decisions (review)
- **policy_version source = DB `client_policy.version`** (NOT `config.ConfigVersion`), per the M10.1
  note + M9.3 `load_judge_policy` precedent. The DB table is the authoritative per-client gate policy;
  the config `JurisdictionPolicy` skeleton supplies the default when no row.
- **`use_decision` is settable post-insert (UPSERT), not append-only** — licensed explicitly by PF-2
  ("a use verdict is settable post-insert"). The verdict is a pure re-derivable function of the
  claim's immutable `use_class` + the CURRENT regime + policy, so only the current verdict is
  meaningful; refresh-in-place beats accumulating stale rows. (Contrast the content-addressed
  append-only M9.3/M9.4 caches.)
- **Hard floor in the gate, not config** — AC2 wants sensitive locked under EVERY posture incl.
  Option 2; `decide_use` floors it before consulting the allow-map, so even a forged sensitive=USABLE
  policy (model_construct / regime_override) is locked. Validator additionally fails such config loud.
- **Gate is CONTACT-only + requires `use_class`** — raises on an account claim (resonance is excluded
  upstream by the M8.2 firewall) and on an untagged claim (M10.2 tags before the gate runs).
- Reused the existing frozen `core.compliance.UseDecision`/`UseReason`/`is_outreach_promotable` and
  `SPAN_COMPLIANCE_USE_GATE` — NO core edit, NO merge/claim-guard edit, side-tables only (PF-2).

## Adversarial audit (4-lens workflow + per-finding verify) — 13 confirmed of 14; all fixed
- **[MED] regime audit column went stale on a verdict-stable jurisdiction re-resolution** (cache
  compared only `(usable, reason)`). Fixed: `_load_cached` returns `regime` too; comparison is
  `(usable, reason, regime)` so a regime change always refreshes the row. (Served verdict was always
  correct — recomputed each call; only the audit column drifted.) + verdict-stable refresh test.
- **[MED] validator didn't enforce the sensitive floor on `regime_overrides`** (loaded silently; the
  runtime floor still locked it, so no fail-OPEN, but the "fail loud" promise was half-done). Fixed:
  `_check` rejects sensitive=USABLE in regime_overrides too; + pure + load-path tests.
- **[LOW ×5, test/guard gaps] all added:** AC2 floor via the regime-override vector; AC7 span
  *attribute* assertions (was name-only — the M9.3/M9.4 span tests assert attrs); AC8 seam-conformance
  (`isinstance(UseGateImpl, UseGate)` + a stub-gate swap — was missing entirely); migration `allow_map`
  SQL-default drift guard (the enum tuple was guarded, the jsonb default wasn't — M9.4 guards both);
  account-entity (first) guard branch; unknown-regime fail-closed (branch c).
- Note: `_resolved_regime` "missing/non-string regime" branch (b) is **unreachable** via a validly
  inserted claim — the `contact.jurisdiction` schema *requires* a string `regime` — so it stays
  dead-but-defensive (no test possible; documented in the test).
