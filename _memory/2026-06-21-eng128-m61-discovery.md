# 2026-06-21 — ENG-128 / M6.1: Account Discovery (mode M1)

## Goal
Grounded-only candidate generation: turn a confirmed ICP's `discovery_strategy` into a stream of
`CandidateHypothesis` via the *expand* pattern, never fabricating an entity. Branch
`m6/discovery-and-pass-a-scoring` (now at `703bd37` = beat0 base incl. the ENG-165 foundation +
M9's `FreshnessState.EXPIRED` contract-delta). Per-branch DB `clue_m6` (host PG, current).

## Key design decision (flagged for review)
M4 has **no discovery interface** — its `Resolver` (and `DeterministicResolver`/`EnrichmentBackend`)
is enrichment-shaped (`resolve(entity, field)`) and structurally cannot *produce* a new entity. The
spec's "Apollo ICP-filtered search serves discovery" was never built. So M6 **owns a new
`DiscoveryChannel` seam** (`discover(query) -> list[CandidateRecord]`), in `discovery_scoring` (NOT
`core` — avoids a re-freeze). It is provider-agnostic + source-keyed, so real providers register
later with zero orchestrator change; promoting it to `core` is a deliberate future re-freeze.

## Files (all under src/clue_research/discovery_scoring/discovery/)
- `hypothesis.py` — `CandidateRecord` / `CandidateHypothesis`; both enforce the **anti-fabrication
  invariant** at construction (must carry `source_record_ref` or `source_url`). `LOOKALIKE_CHANNEL`.
- `channels.py` — `DiscoveryChannel` protocol, `DiscoveryQuery`, `ChannelRegistry` (source-keyed;
  `select()` = strategy channels ∩ bound).
- `stopping.py` — `StoppingReason {MARGINAL_YIELD, BUDGET_CAP, EXHAUSTED, ROUND_CAP}`, `StoppingRule`
  (sliding-window marginal yield + cumulative budget), `marginal_yield`.
- `strategy.py` — `DiscoveryStrategy` (typed view of the opaque `ICPSpec.discovery_strategy` slot;
  fail-fast `from_slot` validation incl. bool-exclusion + range checks) + `DiscoveryConfig` (D7 knobs).
- `query_planning.py` — `plan_queries` via `LLMGateway` (sync `complete`); **queries only, never
  entities**; static fallback with no gateway.
- `orchestrator.py` — `discover()` + `DiscoveryResult`/`ChannelYield`; the expand loop (parallel
  rounds), in-stream dedup, per-channel yield, stopping.
- package `__init__` re-exports the seam. **No PhaseHandler yet** — the DISCOVERY phase is wired in
  M6.2 (it only does something end-to-end once admission exists); M6.1's acceptance criteria are all
  about `discover()`.

## Adversarial review → fixes applied (all 4 findings)
1. **Honest stop reason + no truncation:** `max_rounds` raised to a true safety backstop (1000) and,
   when it fires with work still queued, reports `ROUND_CAP` — never a false `EXHAUSTED` (which M6.5
   reads as "search was exhaustive"). The expand loop provably terminates by queue exhaustion anyway.
2. **Hard budget cap:** the cap is now enforced at *record granularity* mid-round (stop consuming the
   moment cumulative spend reaches it) + `per_query_limit` is enforced (`result[: item.limit]`), so a
   single round can't 10× overshoot the cap.
3. **Dedup bias to under-collapse:** the in-stream dedup key is the candidate's **own registrable
   domain only** (the M2 deterministic strong key), else its unique grounding handle. It no longer
   dedups on `source_url` (a shared platform host would fold two companies) or legal-suffix-stripped
   name ("Acme Group" vs "Acme Holdings"). Authoritative dedup (fuzzy) is M6.2's identity gate;
   over-collapse would silently lose a real account M6.2 can't recover.
4. **Fault isolation:** `asyncio.gather(return_exceptions=True)` — a channel that raises is isolated
   (counted in `ChannelYield.errors`), never aborting the run or discarding peers' grounded results.
Plus slot-validation hardening (range + bool-leak) so a malformed strategy fails at the boundary with
`DiscoveryStrategyError`, not deep in `StoppingRule`.
