# M8 tiny seed — account.resonance.* + contact.facet.* field-class registration

**Date:** 2026-06-22 · **Branch:** `m8/deep-profiling` (off `origin/main` @ 405409a, post full M5/M6/M7/M9 integration + PR#16).
**Scope:** the "tiny seed" agreed before fanning out M8 — register the two deep-pass field-classes as `field_definition` rows (M8.2 part-1 / ENG-136, M8.5 / ENG-154). Pure leaf work, M3-only dep, unblocks M8.4 (population) + M10 (governance). **No migration** (the `field_definition` table already has every column).

## Decisions (after an 8-reader understand workflow + direct reads)

- **Placement = Option B: new `src/clue_research/profiling/fields.py`** (M8 owns its pack), NOT expanding `claimstore/packs.py::CORE_PACK`. Reasons: (1) Option A is hard-blocked by `tests/claimstore/test_field_registry.py::test_governed_field_classes_are_deep`, which asserts EXACT set-equality `resonance=={account.resonance.culture}`, `facet=={contact.facet.recent_post}` under `load_core_pack`; (2) ownership/modularity (open by registration; don't put M8 vertical content in the M1 substrate); (3) precedent — `icp/packs.py` already contributes `account.resonance.research_prestige` and `stage0/fields.py` owns its pack via `claimstore.load_pack`. **`profiling → claimstore` is import-legal** (independence contract bans only worker→sibling-worker; `make contracts` 11/0 green; stage0 imports claimstore today).
- **Leave the 2 CORE_PACK proof rows (`account.resonance.culture`, `contact.facet.recent_post`) untouched and OMIT them from the profiling pack** (re-declaring risks `FieldRedefinitionError` drift; the class is legitimately federated across packs — same pattern as `research_prestige`).
- **Field set = the M8.2/M8.5 canonical lists only** (5 resonance + 8 facet). Resonance: employee_sentiment, attrition_signal, eng_blog_tone, public_frustrations, buying_culture. Facet: nickname, stated_interests, communication_style, public_appearances, publications, causes, alma_mater, career_history. Deliberately did NOT register the golden/eval-referenced extras (`account.resonance.sentiment`, `contact.facet.{hobby,conference_talk,recent_award}`) — they'd be near-duplicates and the offline golden/eval tests don't load this pack, so registering them is illusory-benefit-now. See LATENT GAP below.
- **freshness_ttl:** class defaults are resonance 90d / facet 90d (`config.schema.FreshnessTtls`); per-field `freshness_ttl` overrides shorter (read by the merge + `freshness._scan`). M8.5 AC needs each facet `< core.employee_count` (90d) → every facet field sets an explicit ttl < 90d (graded 45–75d by volatility). Resonance graded 30–90d. NOTE retention (EXPIRED, Doc D §4: sensitive 30d / personal 180d / professional 365d) is `use_class`-keyed at extraction (M10), NOT a field property — do not encode it via freshness_ttl.
- **Governance is STRUCTURAL, not per-field-def.** The DB CHECK `claim_contact_field_requires_governance` (0004) + `core.claim._check_provenance` force every `contact.facet.*` claim to carry `identity_binding`+`use_class`; `core.can_be_promoted` drops WEAK-bound contacts; M10 reads `use_class`. So facet FieldDefs encode NOTHING for this — it's automatic from the `contact.facet` field-class/prefix.
- **gate is advisory.** Only `verification.pre_spend.parse_gate_spec` reads it, and only a JSON `GateSpec` ({requires_official_domain, requires_strong_key}); legacy strings ("deep-pass"/"committee-gated") parse to None. The global `PreSpendPolicy.requires_strong_key` already defaults True for ALL fields, so a per-field `{"requires_strong_key":true}` is redundant. → resonance gate=`"deep-pass"`, facet gate=`"committee-gated"` (matches existing rows), with structural governance documented.
- **use_class_hint home = `FieldDef.validation`** (a `dict[str,JsonValue]` that is round-tripped/drift-checked but NEVER read by value validation — `value_schema` is the separate validator). Facet validation carries `{"use_class_hint": <UseClass>, ...}`. Resonance validation carries the M8.2 sensitivity firewall `{"account_scoped": true, "excludes_named_individual_special_category": true}`.
- **reuse_scope = None (inherit class default TENANT_PRIVATE)** for both classes — matches `research_prestige`/`culture`/`recent_post` precedent; tests assert via `resolve_reuse_scope`.
- **tier_plan:** resonance `("exa_deep","parallel_task")` (registered tier-4 synth, yields resonance; matches research_prestige), facet `("exa_deep",)` (registered tier-4, yields contact.facet). Referencing resolver-absent tier-4 keys is fine (late-bound; waterfall→`no_resolver` empty, not crash). tier-3 review/long-tail source WEIGHTING is M3.3 source-profile work (keys on field-class) — OUT OF SCOPE for the seed.
- **value_schema vocab** is a small custom validator (object/array/string/integer/number/boolean/null/enum/properties/required/items). NO minimum/maximum/additionalProperties — range checks (e.g. polarity -1..1) go in the writer, not the schema.
- **Tests** live in `tests/claimstore/test_profiling_pack.py` (reuse `rollback_conn`; all registry tests live there). DB tests `pytest.skip` without `CLUE_DATABASE_URL` (so `make check` stays green); the governance test is DB-FREE (in-memory `core` claim → validator + can_be_promoted) so it runs always.
