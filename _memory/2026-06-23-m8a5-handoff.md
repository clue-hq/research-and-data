# M8A.5 — Per-account handoff skeleton (references-only, (account,persona)-keyed) — HANDOFF

**For the agent/branch implementing M8A.5.** Read this, then `docs/specs/M8A-project-run-deep-orchestration.md`
§M8A.5, then the current trunk `src/clue_research/api/deep/orchestrator.py` (M8A.1) +
`src/clue_research/core/handoff.py`. Also read [[2026-06-23-m8a1-orchestrator-implementation]].

## Branch
- **Base:** `m8a/orchestrator` (has M8A.0 + M8A.1 + the spec/plan docs). **Branch name:** `m8a/handoff-skeleton`.
- **Parallel-safe with M8A.2 + M8A.3.** Key refinement vs the original plan: **the `references_index`
  folding is ALREADY done by M8A.1** (the orchestrator saves `account` / `committee` / `committee_contacts`
  / `contact:<id>` keys). So M8A.5 is essentially a **NEW FILE** (`api/deep/handoff_skeleton.py`) that
  consumes `AccountDeepResult` — you should need **little or no `orchestrator.py` edit**, which keeps you
  off M8A.3's file and conflict-free. (If you do touch `orchestrator.py`, keep it to attaching the skeleton
  to the result/payload and coordinate, since M8A.3/M8A.4 also touch it.)

## Goal (one paragraph)
Guarantee M12.2's inputs exist and are correctly keyed — **not** build the final `AccountHandoff` (that is
M12.2's pure read over the claim store). Produce the **references-only `(account, persona)`-keyed join**:
for each admitted committee member, attach that contact's `profile_claims` to its handoff `CommitteeMember`
shell, so "this account is M12-ready" is provable. Carry coverage through so a budget-capped / marginal-yield
account reads as **partial, not failed**.

## What M8A.1 ALREADY gives you (build on these, don't rebuild)
- **`AccountDeepResult`** (in `api/deep/orchestrator.py`) carries everything you need per account:
  - `.account: AccountProfileResult | None` — `.claim_refs` (account + resonance, flat).
  - `.committee: CommitteeResult | None` — `.committee()` → `tuple[core.handoff.CommitteeMember(profile_claims=())]`
    and `.members` (each `CommitteeMemberRef`: `contact_entity_id`, `persona`, `role_on_committee`, `*_claim_id`)
    and `.coverage: CommitteeCoverage` (point + band + `channels_not_searched` + framing).
  - `.contacts: tuple[ContactProfileResult, ...]` — each has `.contact_entity_id` + `.profile_claims:
    tuple[core.handoff.ProfileClaimView, ...]` (`claim_id, value_json, evidence_span, source_tier,
    identity_binding, use_class`).
  - `.claim_refs` (flattened across stages), `.cost_cents`, `.sub_phase`.
- **`core.handoff`** (frozen, reuse READ-ONLY): `CommitteeMember(contact_entity_id, persona,
  role_on_committee, profile_claims)`, `ProfileClaimView`, `AccountHandoff`. `CommitteeMemberRef.
  as_committee_member()` already projects to a `CommitteeMember(profile_claims=())` shell.
- **`references_index` is already folded** by the orchestrator's `io.save` at each stage
  (`account` / `committee` / `committee_contacts` / `contact:<id>` → claim-id strings). `save` REPLACES
  the index (see the note on `AccountRunIO.save` in `run_io.py`): if you DO write the index, **load →
  mutate → save the full dict**, never a partial — or you clobber `committee_contacts`.

## What to build
`src/clue_research/api/deep/handoff_skeleton.py` — a pure function, e.g.:
```python
def build_handoff_skeleton(result: AccountDeepResult) -> AccountHandoffSkeleton: ...
```
1. **Project** `result.committee.committee()` (or `.members`) to `(contact_entity_id, persona)`-keyed
   `CommitteeMember` shells, carrying `role_on_committee`.
2. **Join** each admitted member's `ProfileClaimView`s onto its shell by `contact_entity_id`: index
   `result.contacts` by `contact_entity_id`, look up each member, set `CommitteeMember.profile_claims` to
   that contact's `profile_claims`. A member with no matching contact result (capped / not profiled) keeps
   `profile_claims=()` — a valid partial.
3. **Fold** the account+resonance `claim_refs` + committee `claim_refs` + per-contact `claim_refs` into the
   skeleton as **ids only** (they are already in `references_index`; surface them references-only — never a
   `value_json` blob — in whatever shape M8A.2's `PhaseResult.payload` consumes).
4. **Carry `CommitteeCoverage`** (point + band + `channels_not_searched`) through so the account reads
   partial, not failed.
- Define a small `AccountHandoffSkeleton` model (frozen, references-only): the `(account_entity_id, tier,
  account_run_id)` header, the joined `committee: tuple[CommitteeMember, ...]`, the coverage, the cost, and
  the flat `claim_refs`. Keep it claim-bodies-free in the payload surface.

## Integration point
The **M8A.2 `DeepPhaseHandler`** calls `build_handoff_skeleton(deep_result)` to build the references-only
per-account "deep-complete" manifest it returns in `PhaseResult.payload`. So your consumer is the handler
(M8A.2), not the orchestrator. Coordinate the function signature with M8A.2 (or expose it cleanly so the
handler can fold it). You do not need to wait for M8A.2 — define the function + test it standalone against
`AccountDeepResult`; M8A.2 wires it.

## Explicitly NOT in M8A.5
- **No new table.** Compute-on-read from `references_index` + the claim store; the materialized
  `account_handoff` row (if any) is M12.2's call. (Postgres claim store is the sole source of truth.)
- **No final `AccountHandoff` materialization, no `value_narrative`, no `provenance_index`, no fit/intent
  scores** — those are M6/M12. You build the skeleton (the keyed join), not the narrative.

## Acceptance criteria (spec §M8A.5)
- Each committee member in the skeleton is keyed `(account_entity_id, persona)` and carries
  `role_on_committee`; **M12.2 can JOIN `profile_claims` by `contact_entity_id` with no further M8A input.**
- `references_index` / the `PhaseResult.payload` surface contains **only claim ids** — a regression test
  asserts **no `value_json` leaks** into the index or the payload.
- A budget-DENY / marginal-yield-stop account yields a **partial committee with coverage band + named
  unsearched channels**, never a FAILED handoff.
- The skeleton computes **no** fit/intent scores, `value_narrative`, or `provenance_index`.

## Test plan (fakes, no DB — `tests/api/deep/test_handoff_skeleton.py`)
Reuse the fakes from `tests/api/deep/test_orchestrator.py` to produce an `AccountDeepResult` (or construct
one directly), then assert on `build_handoff_skeleton(result)`:
- Each member keyed `(account, persona)` + `role_on_committee`; `profile_claims` joined by
  `contact_entity_id` (a contact result's `ProfileClaimView`s land on the right member).
- A member with no contact result (e.g. capped beyond `committee_size_cap`) → `profile_claims=()`, partial.
- The skeleton/payload surface has **no `value_json`** (assert ids-only).
- Coverage carried through (band + `channels_not_searched`); an empty/partial committee → partial, not fail.
- No scores/narrative/provenance computed.
