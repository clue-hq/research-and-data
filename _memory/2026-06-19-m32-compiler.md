## What M3.2 delivers
The core engine (substrate §3): `compile_field_plan(conn, icp_spec, *, overrides=None) -> FieldPlan`.
A **pure config transform** — reads the ICP spec (M3.1) + M1.3 registry + M3.3 pack field sets; no
source_manifest/resolver/LLM. Computed on demand (NOT persisted — spec allows on-demand; deterministic
because the registry rejects conflicting redefinitions, so a field_key's def is stable).

- Resolves active field set = `icp_spec.field_keys` ∪ each enabled pack's field set (get_pack_field_set),
  deduped first-seen order; per-field `contributed_by` ("icp" / "pack:<key>").
- Materializes each field's `field_definition` from the registry (get_field).
- Partitions `scoring_fields[]` / `deep_fields[]` by `pass_kind` (the two-pass cost dial).
- **Two-tier signal model** (Doc C §1): fields sharing a `signal_class` → `SignalClassLink`
  {signal_class, scoring:[proxy keys], deep:[narrative keys]}.
- Gate carried verbatim. Per-ICP **overrides** (compile param `Mapping[str, FieldOverride]`,
  precedence override > registry default) for tier_plan/gate/freshness_ttl via `FieldDef.model_copy`.
- Validation: missing field_key / unknown pack / override-targets-non-active-field → collect ALL
  diagnostics → raise `CompileError` (no partial plan).
- `plan_hash` (sha256 of canonical content) → content-addressable. `compile_active_icp` convenience.

## Key decisions
- **signal_class on core.FieldDef** (not a registry-extra) → clean read path via get_field/list_fields;
  it's a field's research role (like pass/tier_plan). Additive/optional, backward-compatible.
- **FieldPlan computed on-demand, not persisted** — pure deterministic function; registry immutability
  (FieldRedefinitionError) guarantees a pinned ICP version re-compiles identically. Persistence is a
  future optimization behind the compile seam.
- **Per-ICP overrides = compile parameter** (not an ICP-spec slot yet). The compiler is where
  precedence lives (spec swap-note); the override SOURCE (an icp_spec field-overrides slot) is M5's
  concern later. Avoids re-touching M3.1's committed schema. Criterion 7 satisfied via the param.
- **Conflict note:** the registry's one-def-per-key invariant (register_field rejects conflicting
  redefinitions) structurally prevents "two packs with irreconcilable tier_plan" at compile time;
  the compiler still validates defensively (missing key / unknown pack / bad override → diagnostic).
