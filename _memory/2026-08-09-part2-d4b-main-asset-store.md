# Part II D4 — Round B: the MAIN asset store on `clue_storage`, engine cache demoted

Branch `platform/design-integration`. Contract: `docs/specs/PD-part2-design-substrate.md` (D4),
rulings R-D4-1/4/5/7/8. Round A (the two pure-Python byte trees) is unchanged and intact.

## The shape of it

**Platform storage is the durable home of every design byte.** The Rust engine keeps a
**transient, per-workspace materialization cache** at
`{cache_root}/{workspace_id}/sha256/{ab}/{digest}` — the engine's own layout, untouched, below a
workspace dir. Two directions keep it honest:

- **write-back** after every engine write (`lumen_api/asset_custody.py::register_engine_write`),
  which also re-points `media.location` / `media.thumbnail.location` to
  `{"provider": "clue-storage", "opaque_ref": "<storage key>", "url": null}` (R-D4-4);
- **read-through** before every engine read (`ensure_materialized` / `materialize_scene_assets`).

Pure-Python reads (`/assets/{id}/bytes`, `/thumbnail`, edit source bytes, reference previews,
web-export fonts + image copy, ingestion `resolve_bytes`) skip the cache entirely and read
durable storage by digest.

`create_app(engine_cache_root=None, *, storage=None)`. `app.state.database_path` and
`app.state.asset_store_root` are gone; `settings.lumen_api_database_path` is deleted and
`settings.effective_asset_store_root` is repurposed as the CACHE root (default
`<clue-design>/.engine-cache`, git-ignored). `LUMEN_ASSET_STORE_ROOT` keeps its name.

## Deliberate deviations from the round brief

1. **`_RecordingCore` is the ingestion lane's single write-back chokepoint.** The brief listed
   `uploads.py` / `pdf.py` / `evidence_builder.py` individually, but all three call
   `core.ingest_asset` on the `_RecordingCore` proxy the pipeline already wraps the client in.
   Wiring the write-back there covers all of them with ONE call, leaves the capture modules
   untouched, and makes "did every producer remember?" unaskable. Same for the record
   re-pointing, which now happens before the record is persisted OR embedded in a kit.
2. **`library_font_spec()` stays argument-free and resolves a LIBRARY workspace.** It is injected
   centrally at the `CoreClient` gateway, which has no request (and therefore no tenant) to take
   one from. The font library is one curated, openly-licensed, checked-in-manifest set, so it is
   provisioned into one workspace (`font_library.library_workspace_id()` — the dev-workspace env
   var, the same default `scripts/provision_font_library.py` writes to) and materialized into
   that workspace's cache. The emitted `store_root` is therefore the LIBRARY cache dir, not the
   request's — the helper takes library faces and scene assets from separate roots, so this is
   correct, but see the residual below.
3. **`register_scene_assets` gates on the location resolving to a DIGEST, not a provider label.**
   Matching only `local-store` would have stopped promoting every asset a D4-era producer puts
   in a scene; matching the widened label set would have started promoting `opaque_asset_store`
   handles naming other systems' objects. The digest test keeps the property the label stood in
   for and preserves the existing "skips records without local bytes" behaviour exactly.
4. **`/asset-store/{digest}` skips a candidate whose bytes the backend cannot produce.** The
   brief said "deterministic pick: oldest `created_at`, then `storage_key`". Kept — but as a
   candidate ORDER, not a single row: identical bytes held by several tenants is normal, and
   404ing because some other tenant's row is older (and its blob absent) is a failure the caller
   can neither explain nor fix. Bounded at 50 candidates.
5. **The three `run_*_ingestion` entry points take `storage=` from the dispatching app.** The
   route stages the upload through `app.state.storage`; re-deriving `storage_from_settings()` in
   the worker would let a process with an injected backend stage in one place and read from
   another. Their vestigial `database_path` parameter is deleted with `app.state.database_path`.
6. **`run_agent_turn_preview` / `run_web_agent_turn` gained `workspace_id`.** Not in the brief,
   but load-bearing: the turn's cache and the accept seam's cache must be the same directory or
   every mid-turn generated byte is lost at persist. The `agent_turn_runner` / `web_turn_runner`
   test seams keep their old signatures (only the real runner takes the tenant).

## Residuals for the D4 close-out

- **Font custody is single-workspace.** `library_workspace_id()` reads `LUMEN_DEV_WORKSPACE_ID`.
  Right for one environment and for tests (each test provisions and reads its own copy); not a
  real platform-shared-blob model. Part IV (auth/tenancy) should decide whether the library gets
  a first-class shared namespace, or whether `CoreClient` should carry a per-request tenant.
- **`api_blob_store()` takes the backend from settings, not `app.state.storage`.** Only the
  off-request-thread defaults use it (agent-turn resolvers). A suite that injects a throwaway
  backend into `create_app` AND drives those paths must point `CLUE_STORAGE_FS_ROOT` at the same
  place; the conftest fixture does. Dies with the D2.5A workspace residual at D5.
- **`delete_design_bytes` deletes the blob inside the caller's transaction** (the O5 bridge is
  one transaction per call), so a rollback after the delete leaves a row citing destroyed bytes —
  a dangling ref, never a live row citing destroyed evidence. Documented at the function.
- **Derive/export artifacts are registered but never GC'd.** `design_engine_artifact` blobs
  accumulate: nothing references them durably (the instance row cites a cache-relative path), so
  there is no refcount to drive a sweep. Needs a retention rule, not a refcount.
- **Presign / Part-IV custody.** `/asset-store/{digest}` still resolves across tenants by ruling
  (R-D4-7). The route comment carries the residual; it is the same class as the platform's
  `[B2×presign]` follow-up.

## Pre-existing defect found (reported, NOT fixed — out of scope)

**`tests/api/` poisons the rest of the offline platform suite through the shared database.**
A full-suite run on a PRISTINE DB produces **34 failures** (23 with the three schema-downgrading
`tests/db/test_db_migrations.py` cases deselected), all in `discovery_scoring`, `durable`,
`fleet`, and `sources/test_waterfall`. Reproduces under BOTH `-p no:randomly` and the default
random ordering, on three separate fresh databases — not a seed artifact.

Bisected to `tests/api`, and it has nothing to do with design:

* `tests/db tests/discovery_scoring tests/durable tests/fleet tests/sources` — 529 tests,
  **0 failures** on a fresh DB.
* `tests/design tests/discovery_scoring tests/durable tests/fleet tests/sources` — 592 tests,
  **0 failures** on a fresh DB. (So the D4 tests are not the polluter.)
* `tests/api tests/sources` on a fresh DB → the same 7 `test_waterfall` failures, with
  **no design test in the run at all**. The error is
  `SourceManifestRedefinitionError: source 'apollo' is already registered at version 1 with a
  different definition` — `tests/api` commits `source_manifest` rows that the waterfall tests
  then collide with.
* The separate `test_db_migrations.py` cascade is
  `asyncpg RaiseError: cannot downgrade M8D R2 while entity_research_job fleet tasks exist` —
  again rows an earlier test committed, and the half-downgraded schema it leaves behind fails
  everything DB-shaped after it.

Fix belongs to the platform suite's owner: give the migration smoke its own throwaway database,
and make the `tests/api` source-registry/fleet fixtures clean up (or scope) their committed rows.

## Trap for the next agent

The design-API suite's per-test `FsStorage(tmp_path)` roots + a SHARED Postgres mean stale
`artifact` rows from previous runs point at deleted backends. Any read that resolves ACROSS
workspaces (only `/asset-store/{digest}`) must therefore tolerate a missing blob — which is why
the public read iterates candidates instead of taking the first. Run the suite against a fresh
throwaway database.
