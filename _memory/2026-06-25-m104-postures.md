## Key design points
- **Postures are presets, not branches** — the use-side is the conservative default for every posture;
  the gate floors `sensitive` regardless. A posture is purely the two collection-time settings.
- **The Art. 9 floor stays in the gate**; the `sensitive_overrides` register is the *only* relaxation,
  and it is narrow (per `field_key`), audited (`lawful_basis` + `reviewed_by` required, non-empty), and
  decided per claim in `decide_use` — never surfaced as a regime-wide usable class.
- `store_sensitive` is the seam M10.5 reads (minimization + what erasure/retention must cover); the
  `RetentionTtls`/`LawfulBasisDefaults` M10.5 needs already exist on `config/policy.py` as placeholders.
- Side-tables/additive-ALTER only (PF-2) — no `claim` ALTER, no merge/immutable-guard touch.

## Adversarial audit (4-lens workflow + per-finding verify) — 6 confirmed of 10; all fixed
All LOW/MEDIUM, **no floor breach** (every issue errs fail-safe). Distinct fixes:
- **[LOW] `should_store` ignored a `NOT_STORED` disposition for non-sensitive classes** — a client
  who configs `personal-public: NOT_STORED` ("not retained at all") still got `should_store=True`
  (the docstring claimed non-sensitive is "always storable"). Fail-safe (use still locked), but a
  retention-minimization gap. Fixed: `should_store` returns False for ANY class whose allow-map
  disposition is `NOT_STORED`, then the `store_sensitive` sub-flag still gates `sensitive`. + test.
- **[LOW] `_parse_sensitive_overrides` silently dropped a non-object array entry** (a bare-string
  override → empty register), contradicting the loader's fail-loud contract + diverging from the
  sibling `_parse_allow_map`/`_parse_regime_overrides`. Fixed: validate every element (a malformed
  entry now raises at load). + a load-path negative test. (Fail-safe: a dropped override → floor holds.)
- **[LOW×3, one taxonomy] no no-DB drift guard for the 4 new migration column DEFAULTs** (M10.3
  guards its `allow_map` default; M10.4 omitted it). Fixed: `test_m104_migration_defaults_match_code`
  (regex the migration, assert == DEFAULT_CLIENT_POLICY) — runs in `make check`.
- **[LOW] loader round-trip never read `store_sensitive=True` back** (only the false case). Fixed:
  added the Option-2 load round-trip asserting the true case + `should_store(sensitive)=True`.
